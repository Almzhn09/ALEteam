# Временный показ в Google Cloud Run

Из корня репозитория в авторизованном Cloud Shell запустите `bash deploy/cloud-run/deploy.sh`.
Скрипт создаёт отдельный сервис `ale-archive-preview` в проекте `saq-qurylys`, регионе `europe-west1`. Сервис `saq-qurylys-api` не изменяется. После появления ссылки Cloud Shell можно закрыть.

PostgreSQL работает внутри контейнера; Firebase и Cloud SQL не используются. При запуске восстанавливается снимок реальных материалов из репозитория. Идентификаторы исходных материалов сохраняются в пределах одной сборки. Новые пользовательские изменения при перезапуске теряются: это профиль для показа, а не постоянное хранение.

Пределы: один экземпляр, 1 CPU, 2 GiB памяти, масштабирование до нуля. Первый запрос после простоя требует холодного запуска. Бесплатные квоты зависят от аккаунта и использования; Cloud Build и хранение Artifact Registry могут расходовать кредиты или тарифицироваться. Нулевая стоимость не гарантируется.

Администратор создаётся для текущего аккаунта Cloud Shell. Пароль находится только в `~/.ale-archive-preview/credentials.json`; не отправляйте его в чат. Файлы с секретами исключены из контекста сборки.

После показа удалите только созданные ресурсы:

```bash
gcloud run services delete ale-archive-preview --project=saq-qurylys --region=europe-west1
gcloud artifacts repositories delete ale-archive-preview --project=saq-qurylys --location=europe-west1
```

Проверка локально собранного образа: `mkdir -p .local && node tests/cloud-run-preview.mjs` (Docker, образ `aleteam-cloud-preview:local`, свободный порт 3124). Проверяются исходные данные, страницы, файлы, вход, ответ ИИ со ссылкой на фонд и восстановление после перезапуска. Результат проверки до развёртывания: `docs/cloud-run-preview/validation.json`.

## Постоянный PostgreSQL (Neon)

Создайте отдельный пустой проект PostgreSQL в Neon. В Connect отключите Connection pooling и скопируйте прямую строку с `sslmode=require`. Не отправляйте её в чат или GitHub. В авторизованном Cloud Shell из корня репозитория выполните:

```bash
bash deploy/cloud-run/connect-database.sh
```

Скрипт запросит URL скрытым вводом, соберёт образ, сохранит URL отдельной версией Google Secret Manager и даст сервисному аккаунту сайта доступ только к этому секрету. Новая ревизия использует внешний PostgreSQL; остальные настройки сервиса, пароль администратора и секрет сессий сохраняются. Cloud SQL и Firebase не создаются. Secret Manager имеет собственные квоты и тарифы.

Исходный снимок восстанавливается **только в пустую** базу, одной транзакцией, под блокировкой. В существующей базе архива выполняются только отслеживаемые миграции; чужая непустая база отклоняется. После перезапуска сохраняются аккаунты, сессии и остальные записи БД. Аккаунты и изменения старого временного контейнера автоматически не переносятся: новый постоянный проект начинается с исходных материалов и штатного администратора.

Оригиналы из репозитория восстанавливаются в локальное файловое хранилище при запуске. **Новые пользовательские загрузки ещё требуют отдельного постоянного файлового хранилища**; подключение PostgreSQL само по себе этого не решает. Для обновлений постоянной версии используйте `connect-database.sh`, не запускайте профиль временной БД заново.

Проверка сохранения данных в локальном независимом PostgreSQL: `node tests/cloud-run-persistent.mjs` (Docker, образ `aleteam-cloud-preview:local`, порт 3124). Проверка не подключается к Neon и не затрагивает облачный сервис.

## Обновление общей версии команды

В Cloud Shell, из актуальной общей ветки:

```bash
bash deploy/cloud-run/update.sh
```

Если постоянная БД уже настроена, скрипт пересобирает сайт и обновляет только образ сервиса `ale-archive-preview`; переменные, секреты и настройки входа сохраняются. Если БД ещё временная, запускается подключение Neon скрытым вводом URL. На стороне Cloud Shell требуются Git, gcloud и Python 3; Node/npm/NVM для этой команды не нужны. Строки подключения не печатаются. Контейнер сайта продолжает работать на Node из Dockerfile.

`node --test tests/cloud-run-update.test.mjs` проверяет оба сценария на подставном gcloud и отклонение pooled URL без обращения к облачным ресурсам.

## Срочный выпуск к 23:42, 12 ноября 2026

`bash deploy/cloud-run/release-deadline.sh` в авторизованном Cloud Shell заранее проверяет существование DATABASE_URL; если постоянной БД ещё нет, просит прямую строку Neon скрытым вводом сразу и держит её только в приватном временном файле. Затем ждёт до18:22UTC/23:22Asia/Qyzylorda, получает последний общий коммит и запускает сборку/публикацию, оставляя20минутдоцели23:42. Держите Cloud Shell открытым. Если запустить после указанного времени, сборка начнётся сразу. Другие сервисы проекта не изменяются.

После update/connect-database выполняется `check-public.py`: публичные страницы, все оригиналы/превью опубликованных RU/KK/ENредакций по точному SHA256 и равнозначность4названийгорода в поиске. Проверки только чтения, без тестовых регистраций в рабочей БД. Отсутствие файла или неравнозначный поиск завершает скрипт ошибкой. `ALE_SKIP_PUBLIC_CHECK=1` используется только в тестах с подставным gcloud. Почтовые функции и ИИ с авторизацией этой публичной проверкой не проверяются.
