# TZ-A05 — кандидат трёхъязычной маршрутизации

Обучен 9 ноября 2026 на CPU со случайной инициализацией, seed 2026, PyTorch 2.6.0+cpu, 115 799 параметров. Используются собственные псевдослучайные веса и синтетические фразы ALEteam (CC0-1.0), без готовых моделей/API. Дополнительные алиасы и четыре новых намерения — [extra-classes.json](extra-classes.json). Исторические факты и личные сообщения не входят в обучение.

Старые рабочие training/models/query-model.json и training/report.json **не заменены**. Кандидат лежит в этой папке. В API подключена ограниченная английская ветка при locale=en и ASSISTANT_MODE=local-model: распознаёт намерения помощи по сайту и выбирает авторские английские справки, без свободных исторических ответов. Изменяемые факты берутся отдельно из опубликованной EN-редакции CMS. Это не полная EN-локализация интерфейса/каталога и не универсальный трёхъязычный помощник; Для прежнего диалога RU/KK используют прежние веса. В новой каталожной цепочке кандидат на трёх языках дополнительно нормализует конечный список известных предметных обозначений, например railroad → station; даты/номера/тип определяются правилами. Неизвестные слова сохраняются буквальным условием. [Границы и сквозная оценка](../../docs/artur/full-tz-20261109/SEMANTIC-CATALOG.md). [Детали интеграции](../../docs/artur/full-tz-20261109/CMS-INTEGRATION.md).

## Воспроизведение

Из корня, после установки training/requirements.txt в .local/model-env:

```sh
ARCHIVE_TRAIN_FULL_TZ=1 .local/model-env/bin/python training/train.py
node --import tsx scripts/evaluate-full-tz-model.ts
node --import tsx --test tests/artur-training-candidate.test.ts
```

Без флага тренер сохраняет прежнее поведение и пути. Обучение с флагом перезаписывает только артефакты training/full-tz. Результат конкретного запуска: [report.json](report.json), [веса](models/query-model.json); SHA-256 весов `524be82cff1bbeaf6e4fc322de33188942d227d0aaa648f0041a04c8adc9a380`. Хеши реальных файлов train/validation/test находятся в report.json. JavaScript проверен против всех 817 предсказаний Python на test.

Последний набор и полный before/after: [comparison.json](comparison.json). Это сравнение распознавания намерения, не качества фактического ответа и не сквозной поиск БД. Составной результат 20/20 не отменяет 103 ошибок test. Модель всё ещё может неправильно выбрать тему и не является LLM общего назначения.

В первой попытке кандидат с исходным кодированием имел validation 654/817 и test 604/817. По validation установлено: длинные неизвестные английские вводные фразы доминировали в n-граммах. Для кандидата введена версия признаков english-scaffold-v1: удаление явно перечисленных вводных английских слов, одинаковое в Python/JS; алгоритм кодирования старой модели неизменён. Выбор checkpoint — по validation loss; сохранены все ошибки и оценки test, а не только успехи. После этого report/comparison сохранены, модель больше по test не подгонялась.

У частей нет точных совпадений вопросов. Но темы, алиасы и шаблонная структура общие; удаление вводных слов дополнительно сближает нормализованные признаки. Поэтому это лёгкий авторский набор на известном словаре, не независимая проверка новых смыслов или перевода. Нужен отдельный набор от заказчика/носителей RU/KK/EN и согласованный порог. Новые контакты/публикации модель не должна «запоминать»: они берутся из разрешённой CMS.

Контрольные вопросы tests/fixtures/semantic-catalog.json не имеют точных совпадений с вопросами обеих train-выборок. train.py резервирует их при последующих запусках; текущие веса не переобучались. Это авторский интеграционный набор, не независимая проверка нейросети.
