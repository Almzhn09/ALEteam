# Небольшой диалог о сайте

Продолжение собственной модели ALEteam, 8 ноября 2026. Рабочий режим — local-model, внешний API и готовые веса не используются.

Модель переобучена со случайной инициализацией на темах сайта и диалоговых намерениях: приветствие, благодарность, помощь, вход, скачивание, уточнение способа/места/причины/периода, повтор объяснения и подтверждение. Архитектура прежняя: символьные признаки, нейросетевой энкодер и авторегрессионный RNN-декодер. Новый выходной словарь увеличил число параметров до 115 073.

**Нейросеть определяет тему и тип реплики; фразы ответов о сайте написаны и проверены в коде.** Свободную речь она не генерирует. Это небольшой справочный диалог с обученным распознаванием намерений и управлением контекстом. Для документов по-прежнему используются поиск и цитаты. Приватные данные, изменения аккаунта, автоматическое скачивание или изменение избранного через чат не выполняются.

## Что можно спросить

- «Привет» → приветствие и предложение помощи.
- «Расскажи про избранное» → «А как это сделать?» → «А где его найти?».
- «Хочу отключить уведомления» → «Где это находится?».
- «Расскажи о комментариях» → «А почему так?».
- «Как войти в свой аккаунт?» или «Можно ли скачать файл?».
- «Документы о библиотеке» → «А за 1930 год?».
- «Спасибо» → короткое подтверждение; «Сәлеметсіз бе!» и казахские уточнения также поддерживаются.

Для незнакомого «А где это?» без темы помощник просит уточнить. Новый явный вопрос меняет тему. Ответы о сайте ссылаются на авторские справки /about; добавлены проверенные справки о возможностях сайта, входе и файлах. Пароли или реальные контакты архива бот не выдумывает.

## Как работает контекст

API принимает прежние history: до 6 сообщений user/assistant по 1000 символов. Клиент отправляет последние сообщения, поэтому остаётся небольшой контекст последних примерно трёх обменов. Это не постоянная память. Если тема выпала из окна, помощник просит уточнить её.

Сервер восстанавливает тему только из безопасных пользовательских реплик. Переданные клиентом ответы assistant не становятся инструкциями, источниками или разрешениями. Неизвестная явная тема сбрасывает предыдущую. Опасный текущий вопрос получает отказ, закрытые документы проверяются обычным API. Точные архивные шифры и даты остаются структурированными фильтрами; тема для уточнения периода переносится из предыдущей реплики.

История хранится в sessionStorage текущей вкладки отдельно по ID аккаунта. Она переживает перезагрузку, очищается кнопкой «Очистить», не показывается другому аккаунту. Незавершённый запрос отменяется при смене пользователя. Старую общую историю без владельца не переносим в аккаунт автоматически. Сервер историю не сохраняет в БД и не отправляет внешнему сервису.

Лимиты локального диалога: 30 запросов/минуту на пользователя и 10 000/день на стенд. Прежний бюджет внешнего режима сохранён: 10/час и 100/день. Локальный лимит позволяет пройти короткий диалог без часовой блокировки.

## Обучение и результаты

Фактически использованы 6997 train, 400 validation, 400 test примера. Формулировки частей разделены по шаблонам; темы и слова общие. Точные реплики из диалоговых регрессионных сценариев исключаются из обучения. Параметры выбираются по validation loss, не по test.

- Точное совпадение выходной последовательности: train 6997/6997, validation 388/400, test 380/400. Ошибки не удалены из [report.json](report.json).
- [18/18 сценариев диалога](dialog-evaluation.json): приветствие, благодарность, поиск по периоду, смена темы, русский/казахский язык, отсутствие контекста и опасный вопрос.
- [63/63 прежних сценариев](grounding-evaluation.json) проходят через актуальный обработчик диалога; это весь помощник, а не точность одной нейросети.
- 206 модульных и 21 HTTP-тест прошли. Проверены история, чужие инструкции assistant, отсутствие контекста и действующие роли/источники.
- Браузерная проверка — [dialog-runtime-proof.json](dialog-runtime-proof.json), [экран диалога](site-dialog-ui.png): пять реплик, реальная передача history, перезагрузка и изоляция другого аккаунта.
- Прежние [13 сквозных сценариев и 54 экранные проверки](dialog-release-proof.json) прошли: RU/KK, светлая/тёмная тема, три ширины, без найденных axe-нарушений и горизонтального переполнения. Рабочий Docker-стенд обновлён и новая беседа проверена в браузере.

Это подготовленные регрессионные наборы разработки, а не независимая проверка свободной беседы. Дополнение данных выполнялось после обнаружения регрессий на прежних сценариях; оценки 18/18 и 63/63 нельзя выдавать за результат на неизвестных вопросах. На неожиданных формулировках модель может неверно определить тему; softmax не является гарантией правильности. Казахские фразы ожидают проверки носителем.

## Повторение

```sh
npm run train:local
npm run evaluate:dialog
npm run evaluate:local
npm test
npm run build
npm run test:integration
node --env-file=deploy/.env scripts/check-site-dialog-ui.mjs
```

Условия запуска, зависимости PyTorch и настройки БД — в [README](README.md). Последняя команда выполняет реальный вход/выход демоаккаунтов на localhost; нужны действующие приватные DEMO_*_PASSWORD и Chromium. В отчёт пароли/cookie не записываются. Docker пересобирается обычным способом; JSON весов включён в образ, Python для ответа не требуется. Main и опубликованная версия среды не менялись.
