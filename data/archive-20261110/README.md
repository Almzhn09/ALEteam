# Данные из присланных материалов

[Оригиналы, происхождение и расхождения](../../sources/archive-20261110/README.md).

- `branches.json`: 13 записей из S01, лист «Книга», строки 6–18. Все DRAFT; часы/координаты неизвестны, у трёх записей отмечены пропуск/подозрительные домены. Телефоны и адреса сохранены без домыслов. Назначение: сопоставление с существующими филиалами, текстовые карточки и последующая карта. Не подавать как JSON-импорт документов: это другой тип данных.
- `cms-draft-requests.json`: 18 запросов `POST /api/admin/content` с конкретными `request`, `sourceId`, `sourceKey`, `requiresReview:true`, `publicationAllowed:false`. 11 RU и 7 KK; история разделена на две страницы из-за лимита 10000 символов. Календари разделены по исходным языковым таблицам. Тип PAGE намеренный: профиль BRANCH_PROFILE пока требует точных координат; вымышленные координаты не подставлены. Деловые контакты ещё требуют проверки актуальности.

Обёртка пакета не является готовым endpoint импорта CMS. Отправлять **только `request`** для создания черновика сотрудником с правом `content.write`; idempotency по sourceKey/slug реализовать в адаптере Алимжана до пакетного применения. Создание нового языка существующей страницы — endpoint редакций, не дублирование страницы с новым slug; адаптер должен объединить пары календарей по году и языка комплаенса после редакционного сопоставления. Текущие файлы показывают отдельные исходные тексты и не выдают их за автоматически связанные переводы.

Никакие переходы IN_REVIEW/APPROVED/PUBLISHED не выполнены. PDF/OCR не включены в тексты CMS автоматически. Фонды из XLSB требуют проверки структуры и учётных номеров; не создавать из названия фонда несуществующие описи, дела и документы. Английские тексты и отсутствующие реквизиты — отдельные задачи.
