## Исправления

| Приоритет | Ошибка и последствия | Исправление и доказательство |
|---|---|---|
| P1 | `returnTo` проверял только начало строки. Браузер удаляет табуляцию/переводы строк при разборе URL: путь вида `/\t/evil.example` становится адресом чужого сайта. Нормализация `..` также может превратить относительный путь в `//host`. Это позволяло вывести посетителя с сайта после входа/регистрации. | Контрольные символы, пробелы и обратные слэши отвергаются. Адрес разбирается URL-парсером и после нормализации остаётся локальным, включая запрет протокольно-относительного pathname. Проверены опасные варианты, нормальные пути/запросы/якоря и настоящий вход в браузере. |
| P1 | Фоновая проверка `/me`, начатая до выхода, могла завершиться после него и вновь показать старый аккаунт в интерфейсе. Обратная гонка могла сбросить успешный вход ответом гостя. Сервер при этом правильно запрещал закрытые API, однако старые личные данные могли вновь стать видимыми на общем компьютере. | У ответов есть поколение запроса; смена авторизации инвалидирует предыдущие ответы. Во время входа/регистрации/выхода фоновые проверки не меняют идентичность. Браузерный тест задерживает реальный ответ 200 до выхода и реальный 401 до входа; после их освобождения интерфейс и серверная сессия согласованы. |
| P2 | «Открыть сохранённый поиск» добавлял `contentLang`, который включал прежний поиск архивных документов даже для `scope=cms`. Категория/вид материала/период игнорировались современным каталогом; смена запроса могла терять ограничения. | CMS-поиск сохраняет свой раздел, locale, категорию, тип публикации и период; они входят в запрос API и ключ состояния. Фильтры сохраняются при отправке формы/пагинации и очищаются при переходе в несовместимый раздел. Выход из расширенного поиска действительно возвращает общий поиск. |

API-права, публикационные фильтры, исходные документы и правила модерации не ослаблялись. Не создавались новые сервисы или фиктивное архивное содержимое.
