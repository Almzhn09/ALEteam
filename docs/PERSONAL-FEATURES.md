# Избранное, ответы и уведомления

Реализация E01/E07 — 8 ноября 2026. [API](API.md), [Docker-запуск](../deploy/README.md).

После входа избранное хранится в PostgreSQL и доступно с другой сессии/устройства. Данные привязаны к пользователю из серверной сессии; клиент не назначает владельца. Повторное сохранение не создаёт дубль. Список закрытого документа не выдаёт его метаданные. Лимит — 1000 записей на пользователя; изменения ограничены по частоте.

Без входа сохраняется прежний гостевой список браузера. Перенос в аккаунт выполняется отдельной кнопкой на странице избранного. После успешного переноса соответствующие гостевые записи удаляются. Списки аккаунтов не кэшируются в localStorage; после выхода они не показываются гостю или другому аккаунту. При фокусе окна сессия и список обновляются с сервера. Соседние вкладки узнают о входе/выходе через BroadcastChannel; ownerId ответа защищает от показа чужого или устаревшего результата при смене аккаунта.

В обсуждении доступна кнопка «Ответить». parentId проверяется сервером: только опубликованный комментарий того же документа. Ответ проходит обычную модерацию. Ключ идемпотентности относится к body + documentId + parentId. Уведомление об ответе создаётся лишь после публикации; повторная отправка и повторное утверждение не дублируют его.

Получатель видит уведомления в «Мои комментарии», может отметить одно или все прочитанными, перейти к ответу и отключить отдельно ответы/решения модератора. Изменение настроек действует на новые события. Публикация ответа и его событие, решение модератора и его событие выполняются транзакционно. Собственный ответ не уведомляет автора самого себя.

Уведомления содержат ссылки/статус, без копии текста комментария, email, приватной причины решения или данных отправителя. Чужой ID не позволяет читать/изменять уведомление. Закрытый документ и скрытый ответ/родитель исключают уведомление об ответе при чтении. Решения по собственному скрытому/отклонённому комментарию остаются доступны его автору, пока документ публичен. Уведомления не отправляются по email и не опрашиваются в фоне; для обновления есть кнопка.

Новая миграция: prisma/migrations/202611080002_personal_features/migration.sql. Применяется существующей командой npm run db:migrate; первоначальная миграция не изменялась. В Docker setup автоматически выполняет её до запуска app. Том БД сохраняется; перед обновлением использовать deploy:backup.

Автоматические проверки охватывают два аккаунта, два браузерных контекста, явный перенос гостевого избранного, прямые API-запросы, идемпотентность, CSRF, фильтрацию закрытых документов, настройки, прочтение и восстановление после перезапуска. Командное ревью и ручная проверка на реальных устройствах остаются отдельными этапами.
