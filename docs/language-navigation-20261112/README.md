## Причина и результат

Ошибка воспроизведена до исправления: `/materials/archive-history-1?lang=kk` и `?lang=en` показывали «Нет перевода», хотя русская публикация существовала. Указанные пользователем «Контакты», «История архива» и «Структура» проходят через тот же ContentDetail; ссылки в шапке/подвале не указывали язык доступного оригинала. В списке филиалов и некоторых остальных разделах запрашивалась исключительно редакция языка интерфейса.

Теперь страницы предпочитают опубликованный перевод, а при его отсутствии открывают опубликованную редакцию в исходном языке с заметным сообщением RU/KK/EN на языке интерфейса. Текст оригинала получает корректный атрибут `lang`. Списки филиалов/новостей/памяти/выставок используют существующий общий адаптер `listWithSource`, без дублей редакций. Экспонаты выставки читаются на языке выбранной публикации.

Переключатель языка удаляет устаревшие `lang` и `contentLang`, чтобы ранее выбранная исходная редакция не заслоняла существующий перевод. Остальные параметры и якорь сохраняются. Явный запрос несуществующей `contentLang` по-прежнему показывает выбор доступной редакции; ссылка на неё сохраняет язык интерфейса.

Public API остаётся строгим по locale. Фальшивые переводы, автоматическая публикация и машинный перевод не добавлены; непереведённый текст читается в оригинале. Отсутствующие/неподходящего вида публикации остаются 404. Права и публикационные фильтры не менялись: fallback читает только те же проверенные публичные обработчики CMS.
