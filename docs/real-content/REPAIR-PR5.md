# Исправление фотографий, Windows PDF и интеграция PR #5

## PDF комплаенса

Прежний предел20 секунд заменён настройкой `FILE_PROCESSING_TIMEOUT_MS`: по умолчанию120000, допустимы целые1000–300000 миллисекунд. Настройка читается сервером/CLI и передаётся всем setup/app/jobs в Compose. Пример для существующего `.env` либо `deploy/.env`:

```dotenv
FILE_PROCESSING_TIMEOUT_MS=120000
```

На Linux предоставленный PDF `Аналитикалық анықтама СЖТІТ 2026.pdf`, 13 888 667 байт, повторно проверен целиком за **10 707 мс** при лимите 120 000 мс: **17 страниц**, оригинальный SHA сохранён. Это измерение настоящего файла в Linux, **не подтверждение выполнения на Windows**. Ранний отчёт ниже содержит собственный замер 8384 мс; он сохранён как исторический результат другого прогона. Отдельный тест действительно запускает дочерний процесс, убивает его по меньшему настроенному пределу, проверяет освобождение очереди и ограничение двух процессов. Строгий разбор и ограничения памяти не ослаблены.

`.gitattributes` запрещает преобразование строк в `sources/` и `data/`: SHA исходников не должен зависеть от Windows `core.autocrlf=true`. Проверен Git checkout-filter с этой настройкой; исходные файлы и контрольные суммы не подменяются. На существующем Windows checkout необходимо заново получить затронутые исходники из Git, предварительно сохранив собственные изменения. Полный Windows-прогон и symlink-привилегии этим не объявляются проверенными.

## Целые фотографии

Две прежние копии по81920 байт являются неполными JPEG, неудачное кадрирование CSS к ним не относится. Отключать строгий декодер или дорисовывать недостающие пиксели нельзя.

```sh
npm run sources:images:refresh
npm run content:images
npm run content:images -- --apply
npm run build
npm start
```

`sources:images:refresh` предназначена для повторной загрузки и строгой проверки исходников; она сохраняет новый файл с SHA и обновляет manifest только после успешного полного декодирования. В текущем обследовании оба прежних URL отдают транспортно полный HTTP-ответ, но сам JPEG-объект уже обрезан: **81920 байт**, прежний SHA, а запрос `Range: bytes=81920-` получает **416 / Content-Range: bytes */81920**. Продолжения по этим адресам нет; HTTPS-попытки вернули 503. Повтор запроса не выдаётся за восстановление отсутствующих пикселей. Старые файлы и происхождение сохранены.

Найдены другие полные официальные изображения, проверенные строгим `sharp({failOn:'warning'}).raw().toBuffer()` и просмотром. [Реестр альтернатив и точные HTTP-попытки](../../sources/archive-visual-20261111/recovery/README.md) сохраняет SHA, снимки страниц и подписи RU/KK/EN. Эти изображения не подменяют события повреждённых фотографий.

`content:images` сначала показывает предпросмотр; `--apply` использует штатный private upload→QUARANTINED→APPROVED→PUBLISHED и прежние неактивные технические actor IDs импорта и сверки. Это техническая публикация по поручению пользователя, не подпись сотрудника госархива. Родитель выбирается **для каждого** источника, с проверкой binding/outputHash:

| Источник | Текущее решение |
|---|---|
| `archive-next-generation-ridder` | Полный снимок опубликован к `history-1/ru`; контекст проекта «Архив и будущее поколение», 18 сентября 2026 |
| `reading-room-researcher` | Полный снимок 448×336 опубликован к `reference-reading-room-info/ru` (`archive-reading-room-info`); дата съёмки неизвестна. Для читального зала/услуг, без выдуманного высокого разрешения |
| `elderly-day-altay-2026` | Полный снимок 1280×720 из реальной новости1 октября 2026 подготовлен как источник; состояние **`context_required`**. Подходящий событийный CMS-родитель не создан автоматически; новая выдуманная новость ради фотографии не добавляется |
| `thematic-exhibition-altay`, `open-day-altay` | Прежние неполные JPEG сохранены; состояние **`incomplete_source`**, не опубликованы как целые |

Повтор использует существующие файлы. Ручной отзыв, отклонение, незавершённая работа редактора, закрытый родитель и изменённая редакция не обходятся. Полный снимок социального визита не используется как изображение читального зала, выставки Халиловой или другого события.

Изображения не копируются в `public/`. Выдача, отзыв и права по-прежнему проверяются `/api/material-files`; главный экран выбирает только опубликованное CMS-вложение. Афиша остаётся историческим материалом и не используется как текущее объявление или hero-фото.

Обычный `content:apply`/Docker setup тоже прикрепляет только полностью проверенные доступные фотографии. Заблокированные источники перечисляются отдельно в отчёте, без ослабления декодера и без остановки остальной готовой платформы. После получения полных оригиналов повторный импорт добавит их через тот же workflow; ручной отзыв учитывается и при смене редакции родительского материала.

## PR #5

Подтверждены исходная ветка `frontend/alinur-visual-v2`, head `1438987` и целевая `artur-full-tz-20261109`. [PR #5](https://github.com/Almzhn09/ALEteam/pull/5) **слит** в общую ветку; GitHub подтвердил **MERGED**, merge-коммит **`6a55d80`**. Настоящий merge сохраняет авторство и frontend/server историю. Разрешены конфликты главной, чтения материалов, шапки, рекомендаций, ссылок и словарей. Сохранены локальные шрифты, защита ссылок на источники, актуальные серверные API и переход к странице4 S06. Дублирующиеся редакторы CMS-вложений удалены со страницы редакции, остаётся новый редактор PR #5.

**Историческое состояние раннего прогона:** среда возвращала 403 для официального сайта; тогда доступ домена `e-arhiv.vko.gov.kz` был блокировкой. Этот контекст сохранён, но **не описывает новое обследование11 ноября**: HTTP-доступ теперь работает, и обнаружен неполный объект на самом доступном URL (81920 байт, Range416). Сохранённый сетевой черновик сам по себе не доказывает применённую конфигурацию; успешный HTTP-ответ сам по себе не доказывает целостность JPEG. `complete_decode` присваивается только после настоящей загрузки и полного разбора.
