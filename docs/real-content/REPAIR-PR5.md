# Исправление фотографий, Windows PDF и интеграция PR #5

## PDF комплаенса

Прежний предел20 секунд заменён настройкой `FILE_PROCESSING_TIMEOUT_MS`: по умолчанию120000, допустимы целые1000–300000 миллисекунд. Настройка читается сервером/CLI и передаётся всем setup/app/jobs в Compose. Пример для существующего `.env` либо `deploy/.env`:

```dotenv
FILE_PROCESSING_TIMEOUT_MS=120000
```

На Linux предоставленный PDF `Аналитикалық анықтама СЖТІТ 2026.pdf`,13888667 байт, проверен целиком:17 страниц, оригинальный SHA сохранён. Это проверка реального файла, а не замер Windows. Отдельный тест действительно запускает дочерний процесс, убивает его по меньшему настроенному пределу, проверяет освобождение очереди и ограничение двух процессов. Строгий разбор и ограничения памяти не ослаблены.

`.gitattributes` запрещает преобразование строк в `sources/` и `data/`: SHA исходников не должен зависеть от Windows `core.autocrlf=true`. Проверен Git checkout-filter с этой настройкой; исходные файлы и контрольные суммы не подменяются. На существующем Windows checkout необходимо заново получить затронутые исходники из Git, предварительно сохранив собственные изменения. Полный Windows-прогон и symlink-привилегии этим не объявляются проверенными.

## Целые фотографии

Две прежние копии по81920 байт являются неполными JPEG, неудачное кадрирование CSS к ним не относится. Отключать строгий декодер или дорисовывать недостающие пиксели нельзя.

```sh
npm run sources:images:refresh
npm run content:images
npm run content:images -- --apply
npm run build
npm start
```

Первая команда получает полный ответ официального сайта, проверяет размер и полное декодирование, сохраняет новый оригинал под именем с SHA и атомарно обновляет manifest только после проверки обеих фотографий. Неполные оригиналы сохраняются как доказательство исходного сбоя. Интерфейс берёт SHA/размеры из manifest, поэтому у него не остаётся старой жёстко записанной контрольной суммы.

`content:images` сначала показывает предпросмотр. `--apply` прикрепляет проверенные фотографии к опубликованной странице истории штатными private upload→QUARANTINED→APPROVED→PUBLISHED функциями, используя прежние неактивные технические actor IDs импорта и сверки. Это техническая публикация по поручению пользователя, не подпись сотрудника госархива; новых учётных записей/паролей не создаётся. Повтор использует существующие файлы. Отзыв, отклонение, незавершённое действие редактора, закрытый родитель и изменённый текст страницы не обходятся. Неполные источники остаются заблокированы; ненулевой результат команды не объявляется полной публикацией.

Изображения не копируются в `public/`. Выдача, отзыв и права по-прежнему проверяются `/api/material-files`; главный экран выбирает только опубликованное CMS-вложение. Афиша остаётся историческим материалом и не используется как текущее объявление или hero-фото.

Обычный `content:apply`/Docker setup тоже прикрепляет только полностью проверенные доступные фотографии. Заблокированные источники перечисляются отдельно в отчёте, без ослабления декодера и без остановки остальной готовой платформы. После получения полных оригиналов повторный импорт добавит их через тот же workflow; ручной отзыв учитывается и при смене редакции родительского материала.
