# R-B01–B05: минимальный совместимый контракт

Основа3869be7; ветка backend/alimzhan-real-content-v2. Контракт реализован. [API](API.md), [запуск/перенос](OPERATIONS.md), [проверки](proof/VALIDATION.json), [выполненные ответы](proof/API-EXAMPLES.json). Исходная фиксация интерфейса сохранена в6a3cf4a.

MaterialKey остаётся `{kind:document|cms,id}`. Справочники фондов и газет — отдельные сущности, без вымышленных Fund/Inventory/Case/Document. Browser-safe типы: src/contracts/real-content.ts.

- GET `/api/search?q=&scope=all|document|cms|fund|newspaper&locale=ru&page=1&pageSize=20`: SearchResult с counts и discriminated SearchHit. Старый `/documents` не меняет предмет поиска. scope=all ищет все типы; фильтры category/contentKind/годы AND применяются к подходящим типам, не теряются молча.
- GET `/api/directories/funds` и `/api/directories/newspapers`: q,sourceId,page/pageSize,sort=source|title. GET `/:id`; GET `/export` с теми же фильтрами отдаёт whitelist JSON всего набора без admin/raw полей. Строки/номера/периоды/происхождение сохраняются; edition/notes показывают2018 против подписи2026. Неизвестный держатель/branchId —null. Никаких тысяч CMS/fact ради FK.
- GET `/api/discovery/materials/:kind/:id/attachments?locale=ru`: AttachmentRef[]. GET `/api/material-files/:id[?download=1]`, `/text`. Файл привязан к опубликованной редакции CMS, мастер/PNG-превью раздельные. DOCX — настоящий оригинал и абзацный текст; PDF — реальные страницы. Права и SHA проверяются при каждом чтении, отзыв прекращает выдачу. Старые `/files` сохранены.
- POST `/api/discovery/materials/:kind/:id/explanation` `{locale,sourceRevision?}` и GET `.../related?locale=&limit=5`: прежние Explanation/MaterialRef[], теперь оба MaterialKey. Старые `/documents/:id/explanation|related` сохраняются. CMS body может быть источником объяснения; вложение предоставляет более полный исходный текст/страницы/абзацы. Номер страницы DOCX не выдумывается, fragment.paragraph отдельный.
- Подписки сохраняют `/me/topic-subscriptions`; filters получает совместимые scope=all|document|cms и contentKind,category. По умолчанию q/category/год ищутся и в CMS; архивные структурные fund/inventory/case/type/reference фильтры сохраняют только архивный предмет. Справочники не превращаются в MaterialKey/уведомления о новом документе.
- Админское CMS-вложение: POST `/admin/content/:id/attachments` с revisionId,name,mimeType,expectedBytes,expectedSha256,rights,sourceNote; PUT `/admin/material-files/:id/content` (raw + If-Match); POST `/review` и `/publish`, GET списка/статуса. Те же content.write/review/publish, область филиала, независимый review, неизменные bytes. Публичная публикация не происходит от выбора файла. Точный DTO/ошибки будут в API.md.

Обычный setup использует реальный пакет; ALLOW_DEMO_SEED по умолчанию0. Синтетика разрешена только явно в изолированных тестовых БД. Перед адресным снятием прежних фикстур делается закрытый backup; пользовательские записи/комментарии/аккаунты не сбрасываются. Публикация проходит существующий CMS state machine. Технические сервисные этапы импорта/проверки обозначаются автоматическими, не подписью сотрудника архива.

Артуру: explainFragments получает прежний AuthorizedText + optional paragraph, права остаются транспортными. Алинуру: материал сайта открывается существующей CMS-страницей; registry строки имеют собственный kind/href и не показывают вымышленную цифровую копию. До реализации использовать статусы отсутствия данных, не mock-успех.
