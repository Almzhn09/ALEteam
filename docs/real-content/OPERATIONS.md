# Запуск и перенос реального наполнения

Обычный режим — `ARCHIVE_CONTENT_MODE=real`, `ALLOW_DEMO_SEED=0`. Он используется новыми setup/.env.example/Compose. Вымышленные данные не становятся реальными от изменения isDemo: известные20 карточек адресно снимаются с публичной выдачи. Исходные строки, комментарии, избранное и учётные записи сохраняются; публичные surfaces перепроверяют текущие права. Справочники не создают Fund/Inventory/Case/Document.

## Локальный запуск

```sh
npm ci
npm run setup:local
# Запустить PostgreSQL по основной инструкции; существующий .env не перезаписывать.
npm run db:migrate
npm run content:preview
# Сохранить закрытые оригиналы/реестры источников в native files store для backup:
node --env-file-if-exists=.env scripts/persist-source-bundle.mjs
npm run content:apply
npm run build
npm start
```

Preview только читает БД и пишет закрытый отчёт `.local/real-content/preview.json`. Apply создаёт предоставленные CMS-редакции/филиалы,3171 справочную запись,53 языковые редакции в39 CMS-материалах,27 связей вложений с21 оригинальным файлом, факты/темы/подборки и затем снимает известные фикстуры. Полная привязка sourceKey/locale→ID/revision находится в закрытом applied.json и в [публичной технической передаче](proof/PUBLISHED-MAPPINGS.json). Повтор проверяет digest/исходные bytes/текущий payload, не создаёт новые CMS/file/fact/notice rows и не возвращает отозванные материалы. В рабочем повторе все страницы unchanged, снятых фикстур0.

Перед изменением **непустой** БД apply требует/создаёт закрытый backup. Локально используется pg_dump либо единственный PostgreSQL-контейнер, чей опубликованный порт соответствует DATABASE_URL; неоднозначный контейнер не выбирается. Пароль передаётся через окружение, не командную строку/лог. Сохраняются database.dump и files.tar с SHA manifest/идентификатором целевой БД в `.local/real-content/backups`, права0700/0600. Существующий `REAL_CONTENT_BACKUP_MANIFEST` принимается только после проверки идентичности БД и обоих файлов. Для удалённой непустой БД нужен pg_dump либо проверенный manifest; ошибка не разрешает обходить backup.

Серверный результат Алимжана интегрирован с проверенным содержанием Артура. На свежей изолированной установке проверены53 языковые редакции и повтор без дублей; [актуальный отчёт](../artur/real-content-v2/STATUS.md). Предыдущие49 редакций — исторический срез серверной ветки, а не текущее количество. Пароли/резервные копии/.env в Git не попадают. Частная резервная копия остаётся в `.local/real-content/working-backup.json` по ссылке на manifest; не публиковать её вместе с отчётом.

Ручная правка любого поля старого источникового DRAFT вызывает SOURCE_IMPORT_CONFLICT вместо перезаписи: проверяется весь нормализованный payload, а не один body. Разрешён повтор после устранения конфликта/прерванного импорта. Старое сопоставление Branch сохраняется. Скрытый существующий филиал с другими потенциально публичными карточками/публикациями не открывается автоматически ради профиля: BRANCH_VISIBILITY_REVIEW_REQUIRED. Настоящие записи не сбрасываются общим reset.

### Обновление существующего пакета

`content:apply` также обновляет прежний пакет из49 редакций до проверенного пакета из53. Сначала создаётся/проверяется резервная копия. Для неизменённой публичной редакции импорт создаёт следующую редакцию через обычный CMS workflow; ID материала и slug сохраняются, прежняя редакция архивируется. Прежние мастеры остаются привязаны к ней и недоступны по публичному route. Тот же оригинал получает новую связь с новой редакцией. Привязки импорта сохраняют предыдущие ID/хеши в `data.versions`; изменения автоматических фактов сохраняют предыдущие данные/доказательства, ID факта и запись аудита.

Предварительная проверка останавливает импорт при редакторской правке, более новой редакции, отозванном вложении заменяемой редакции или закрытом филиале. `SOURCE_IMPORT_CONFLICT` требует сверки с редактором; удалять правку или самостоятельно снимать отзыв ради повторного импорта нельзя. Несовпадение bytes исходника остаётся ошибкой. Одновременный второй apply получает `SOURCE_IMPORT_BUSY`; первый импорт продолжает работу. Если импорт прервался после проверки файла, повтор завершает обработку и наложение подготовленного OCR до публикации.

Публикация проходит **тот же** CMS state machine: DRAFT→IN_REVIEW→APPROVED→PUBLISHED, разные actor IDs, аудит, outbox. Два неактивных технических пользователя без паролей/сессий явно названы автоматическим импортом и сверкой ALEteam. Это техническая встречная проверка подготовленных источников по поручению пользователя, не вымышленная подпись сотрудника госархива. Самостоятельный вход этих акторов и служебные права браузера не создаются. Для настоящей работы редактора используется прежний `staff:bootstrap`/админские роли с собственными закрытыми credentials; действующие учётные записи не меняются.

## Docker и восстановление

```sh
npm run deploy:setup
# Проверить закрытый deploy/.env: ARCHIVE_CONTENT_MODE=real, ALLOW_DEMO_SEED=0.
docker compose --env-file deploy/.env -f deploy/compose.yaml --project-name ale-real up -d --build app
# При необходимости:
docker compose --env-file deploy/.env -f deploy/compose.yaml --project-name ale-real --profile workers up -d jobs
```

Свежий setup автоматически импортирует реальный пакет. Синтетических пользователей/20 учебных документов в обычном setup нет. На обновлении непустой установки сначала штатный `deploy/backup.mjs`; upgrade выполняется с проверяемым backup, не принудительным reset. Подробные команды backup/restore — прежняя deploy-инструкция. Restore только в новый проект/пустые volumes, с соответствующими runtime/tools одной версии. При работе за Cloud proxy сборка использует существующий секрет proxy_ca и проверку TLS; отключение TLS не требуется.

Для **обновления уже запущенного** реального проекта сначала соберите новые runtime/tools, затем выполните из корня репозитория:

```sh
docker build --target tools -t aleteam-tools:local .
docker build --target runtime -t aleteam:local .
npm run deploy:upgrade -- --project ale-real --env deploy/.env
```

В managed Cloud к обоим `docker build` добавляется `--secret id=proxy_ca,src="$CODEX_PROXY_CERT"`. Команда upgrade требует существующий работающий app и режим real. Она приостанавливает app/jobs, сохраняет согласованную копию DB/files и SHA manifest с идентичностью БД, затем передаёт копию setup через отдельный закрытый read-only volume. Контейнер setup проверяет identity/оба SHA до импорта. Хосту не нужен pg_dump; контейнеру tools не нужны Docker socket/пароли хоста. Служебные том/контейнер/transfer удаляются, оригинальная копия и отчёт остаются в `.local/deploy-upgrades`. БД и основной files volume не сбрасываются.

Ошибка до начала миграций возобновляет прежние контейнеры. После начала изменений сайт остаётся приостановленным: диагностика сохранена в закрытом setup.log; восстановление выполняется в **новый** проект. Backup теперь сохраняет SHA runtime и tools; restore выбирает именно эту пару, а не случайный новый tag. Образы должны оставаться в локальном Docker либо быть отдельно сохранены оператором: database.dump/files.tar не включают image layers. Старые manifests без toolsImage продолжают использовать явно настроенные runtime/tools. Обновлять восстановленную старую версию следует той же командой upgrade.

Private volume содержит мастеры, превью, OCR, а также source-bundles/archive-20261110, archive-public-20261111, archive-reference-20261110. Копирование EXCL+SHA не перезаписывает оригинал; source README — редакционная документация, не immutable original. Полные source bundles, внутренний VPN-лист из постороннего листа XLS и разработческое ТЗ не получают публичного файлового route. Предоставленные аналитические PDF комплаенса и уведомления опубликованы: в исходном уведомлении прямо сказано об их размещении на сайте. Публичны только разрешённые отдельные DOCX/PDF с штатной проверкой прав. Весь набор новых таблиц и файлов проходит обычный pg_dump/files.tar backup.

При расширении реестра17→21 исходник `persist-source-bundle.mjs` проверяет неизменность оригиналов/извлечений/OCR и сохраняет обе версии корневого `manifest.json` в закрытом `.manifest-history/<sha256>.json`. Активный manifest переключается атомарно после проверки всех файлов. Повтор не создаёт новые версии; symlink и конфликт оригинала останавливают обновление. История manifest входит в тот же files.tar и не получает публичного URL.

[Актуальная проверка](../artur/real-content-v2/proof/docker.json): Docker6/6 на интегрированном реальном корпусе — свежий default setup, исходные DOCX/PDF/OCR, повтор, поиск/превью, backup и точное восстановление нового проекта. Прежние21/21 Docker также прошли в явно выделенном fixtures-режиме. Временные проекты/сервисы workers/volumes и env-файлы тестов удалены; backups остаются закрытыми. Старый рабочий stand/чужие ветки не уничтожались.

## Изолированные фикстуры и CI

`prisma/seed.ts` требует ALLOW_DEMO_SEED=1 и имя `_test` БД либо явный SYNTHETIC_FIXTURE_DATABASE=1 в отдельном Docker test project. Docker fixtures-режим задаётся **явно** ARCHIVE_CONTENT_MODE=fixtures. Это не штатный режим просмотра. Restore fixtures-стенда с ALLOW_DEMO_SEED=0 не добавляет новый корпус. Нельзя включать эти флаги на рабочем источниковом проекте.

`test:real-content` очищает только `_test` БД; проверяет весь справочник, пользовательские данные, конфликт заголовка без изменения body, повтор после частичной работы, CMS upload/права/отзыв, OCR/абзацы и CMS-подписку. `test:uploads` теперь использует собственный временный файловый каталог: рабочие CMS-вложения не считаются «осиротевшими тестовыми файлами» и не удаляются тестом.

`test:real-content-upgrade` использует только `_test` БД и отдельный временный storage: новая редакция/история/прежние ID, повтор без дублей, редакторский конфликт/отзыв/закрытый филиал, возобновление OCR и защита от параллельного импорта. В CI запускается отдельным шагом после основной real-content suite; suites, использующие одну тестовую БД, запускаются последовательно.

CI включает новые HTTP и Docker real-content проверки после прежних suites. Все эквивалентные команды выполнены локально; удалённый GitHub Actions run не объявляется наблюдавшимся. История/цены/языки/официальная действительность не становятся независимо принятыми из-за автоматического теста.

## Границы

Не предоставлен источник личных фондов; неизвестная принадлежность фондов/газет остаётсяnull. Даты/номера/названия сохраняются из источника,2018 не превращается в2026. Новые архивные дела/сканы не выдумываются. OCR не назван проверенной транскрипцией или вероятностью истинности. Антивирус/внешний хостинг/домен/публичная HTTPS-приёмка не имитируются. ИИ остаётся собственной query-model + grounded extractive/glossary/ranking, без скрытой внешней LLM.

Новые frontend-сценарии — Алинур: `/search` вместо архивного `/documents` для общего поиска, отдельные registry экраны, attachments/paragraph/page, общий CMS explanation/related, sourceFileLink для namespace material-files. Native API no-store необходимо сохранять; картинки с отзывом нельзя навсегда кешировать оптимизатором. Артур принимает редакционные решения/формулировки/языки/новые эталоны на реальном корпусе. Два сохранённых снимка показывают действующие реальные страницы, а не заменяют новую художественную/языковую приёмку.
