## Что загружается

Обычные setup и Docker используют `ARCHIVE_CONTENT_MODE=real`, `ALLOW_DEMO_SEED=0`:

- 53 языковые редакции в 39 CMS-материалах, 13 филиалов;
- 21 неизменный оригинальный DOCX/PDF, 27 связей вложений с редакциями;
- 1705 групп буквальных номеров фондов и 1466 газетных строк хранения;
- восемь тем, три места, девять источниковых исторических событий.

Это не 3171 оцифрованное архивное дело: предоставленные справочники не содержат таких копий. На чистом запуске вымышленных архивных документов нет. При обновлении известные старые фикстуры снимаются адресно; записи пользователей, комментарии и избранное сохраняются. Повтор импорта не создаёт дубликаты и не возвращает отозванные материалы. Ручные правки защищены конфликтом, непустая база — проверяемой закрытой резервной копией.

В редакционном пакете 53 языковые заявки сгруппированы в 34 логические группы. Итоговые 39 CMS-материалов сохраняют уже опубликованные серверные ID, отдельные языковые PDF и дополнительные справочные страницы; это не лишние вымышленные публикации. Реестр файлов пакета содержит 29 оригиналов разных форматов; 21 поддерживаемый DOCX/PDF подключён как CMS-вложения, остальные используются как исходники справочников/ссылки на оригиналы.

## Сверка содержания

Часы центрального архива — 8:00–17:00, читального зала — 9:00–16:00 по будням. Сырой контактный XLS не публикуется целиком: посторонний лист содержит сетевые сведения; два явно подозрительных адреса электронной почты исключены без выдуманной замены. Пустые контакты/координаты/вакансии не дополнялись догадками.

Постановление №142 принято 2 июня 2026 года и касается филиалов. Дата и номер визуально сверены со страницей 4 исходного PDF. OCR рукописи ошибается в этих реквизитах даже при высокой средней оценке страницы; вопросы о дате используют проверенные метаданные, а не ошибочное распознавание. Полный OCR не объявлен выверенным, числовой confidence не придуман.

Календари сохранены целиком с адресными примечаниями; спорные даты не превращаются в структурированные события. Версии фондового/газетного справочника и нормативных приложений указаны честно. Предоставленные аналитические PDF комплаенса опубликованы вместе с уведомлениями: источник прямо сообщает об их размещении на сайте. Дополнительное ТЗ организаторов используется как проектное требование, а не историческая публикация.

## Передача Алинуру

Входные данные и серверные контракты готовы; отдельной новой визуальной ветки на момент сдачи не принято. Оставшаяся работа находится в [R-F01–R-F05](../../../задачи/ТЗ-2026-11-10/Алинур-визуальный-этап.md): композиция и отступы, интерфейс общих результатов/справочников, CMS-просмотр оригиналов и объяснений, реальные фото, сдержанная анимация, reduced-motion и финальная визуальная приёмка. Прежний интерфейс источникового импорта из `frontend/alinur-discovery-v2` интегрирован; это не подтверждает готовность всего нового визуального этапа.

- Изображения и подписи брать из `sources/archive-visual-20261111/manifest.json`; прошедшую афишу не показывать текущим приглашением, фото филиала не называть центральным зданием.
- Короткие RU/KK/EN тексты доступны в `data/artur/real-content-v2/ui-copy.json`. Главная, подвал, справка и часы уже поправлены; не возвращать старые технические оговорки и примеры фиктивных дел.
- Чтение опубликованного наполнения — из API. Общий поиск `/api/search`, справочники `/api/directories/funds` и `/api/directories/newspapers`; [серверная передача](../../real-content/HANDOFF.md).
- У источников помощника появились отдельные типы `fund`/`newspaper`; они не являются Document. Разрешённые ссылки на оригиналы ведут через `/api/material-files/…`; не копировать ограниченные вложения в public ради отображения.
- Нет настоящих агрегатов популярности — показывается редакционная рекомендация, без придуманных просмотров. Предпочтения влияют на подборку; отказ возвращает редакционную выдачу.

## Запуск и повтор

Обычный локальный запуск описан в [README](../../../README.md) и [OPERATIONS](../../real-content/OPERATIONS.md): миграции → `npm run content:preview` → `npm run content:apply` → build/start. Не использовать синтетический seed для наполнения сайта и не сбрасывать рабочую базу.

Собственная проверка запускается после build: `node --env-file=<закрытый тестовый env> --import tsx scripts/check-real-content.ts --native-setup`. Она требует отдельную БД с точным именем `archive_release_test`, отдельный FILE_STORAGE_ROOT, Chromium и Playwright FFmpeg. Проверка сама изменяет тестовый корпус для отзыва/новой публикации; повтор выполняется на свежей собственной тестовой базе, не на общем стенде. Остальные команды: `npm test`, `npm run i18n:check`, `npm run test:cms-assistant`, `npm run test:real-content`, `node tests/real-content.deploy.mjs` с выделенными тестовыми конфигурациями.
