# R-A01/R-A02: готовое содержание и изображения

Основа — интеграционная ветка `artur-full-tz-20261109`; работа Артура — `artur/real-content-v2`. Новый запуск Артура разрешён пользователем 11 ноября. Старый этап и синтетические доказательства не заменяют эту передачу.

## Алимжану: пакет для R-B01/B03

`data/artur/real-content-v2/publication-manifest.json` — **53 языковые записи / 34 материала**, включая 13 филиалов. Решение по содержанию принято: `PUBLISH`, кроме конкретно перечисленных исключений. Это готовые тексты и поля текущего `contentPayload`, а не новый CMS/HTTP-контракт. Подготовка не меняет БД и не выдаётся за состоявшуюся публикацию.

`files.json` — 29 настоящих файлов с путём, SHA-256, исходным названием, качеством текста и решением о доступности. Разобранные вложения из 7z сохранены в `sources/archive-publication-20261111/attachments/`. Они воспроизводятся `python scripts/prepare-real-publication.py` без пакетов Python (нужен libarchive). Бинарные DOC/DOCX/XLSB не исполнять: только просмотр/разбор/скачивание по штатной политике файлов.

Порядок: preview → существующие CMS-черновики → проверка другим участником → штатная публикация. Служебный автор/рецензент проекта не называется сотрудником госархива. Все языки с одинаковым `materialKey` относятся к одному CMS item. `sourceKey` сохранить как привязку источника: она нужна для фактов/хронологии. `branchSourceKey` требует существующего сопоставления филиала; `null` в подготовительном request не является разрешением публиковать отвязанный профиль.

`attachments` содержат логические ключи из files.json. Адаптер разрешает их в реальные file IDs после реализации общей связи CMS-файла; выдуманного документа/фонда для FK не создавать. DOCX/PDF имеют реальные исходники. Восемь PDF комплаенса показаны отдельными двуязычными публикациями; машинный OCR не объявляется выверенным. В S06 визуально проверены дата/номер/предмет, русский текст начинается на странице 4.

S01 публикуется только по контактному листу: сырой XLS **не прикладывать** из-за постороннего VPN-листа. Два подозрительных email исключены из публичного payload; остальные адреса/телефоны доступны. Нет выдуманных часов, координат и телефона Марқакөл. Пустое поле заместителя не становится вакансией. Календари целиком доступны с точечным примечанием, спорные события не попадают в структурированные факты. Версии S09/R01–R05 сохранены честно.

## Алинуру: реальные тексты и визуальные материалы

У каждой записи есть `section`, язык, заголовок и полный body для макета. После импорта UI читает API, а не держит вторую копию БД в клиенте. Основные разделы: history, contacts, structure, calendar, compliance, branches, fonds, services. История разделена по существующему лимиту CMS, RU/KK календари объединены одним slug на год. Полноценный EN исходник отсутствует у большинства материалов: языковой fallback честно показывает язык источника.

`sources/archive-visual-20261111/manifest.json` — четыре проверенных изображения с alt/подписью/происхождением/размерами и назначением. Две настоящие фотографии встреч, одна архивная афиша и страница предоставленного постановления. Афиша прошедшего мероприятия не подаётся как текущее приглашение; фото филиала не называется центральным зданием. Автор снимков на исходной странице не указан, кредит — официальный сайт архива, без вымышленной свободной лицензии.

Для главной подходят фотография работы с посетителями/выставки, текст рядом, без текста поверх лиц. Афиша — только в историческом контексте. Страница постановления — карточка документа/структуры, без обрезки реквизитов. Источник и подпись доступны из карточки. Производные/адаптивные размеры и интеграция в UI — R-B03/R-F04; ограниченные CMS-файлы не копируются в public/ ради обхода прав.

## Проверки передачи

`curation.json` содержит 26 источниковых утверждений (3 места, 14 алиасов, 9 событий), 6 обеспеченных содержанием тем, 9 редакционных материалов и 3 связи с цитатами. Первые три рекомендации — история архива, календарь 2026, справочник фондов. «Фотографии» не выдаются за цифровую архивную коллекцию. Фиктивной популярности нет.

`prepareRealCuration` принимает **текущие публичные** CMS source bindings и разрешённые place/topic IDs и возвращает payload существующего fact API. Для проверки подготовки: `node --import tsx scripts/prepare-artur-facts.ts --real --sources <bindings.json> --places <places.json> --topics <topics.json> --out <facts.json>`. В первом проходе места/темы готовы, зависящие от них факты помечены blocked; после их штатной проверки повторная подготовка разрешает связи. Сам CLI ничего не публикует. Сохранить старые sourceKey при импорте обязательно.

Движок объяснения принимает CMS, URL разрешённого текста `/api/material-files/:id/text` и номер абзаца DOCX, не придумывая номер страницы. Транспорт/правила доступа остаются за Алимжаном. Retrieval проверяет весь body (включая инструкции за пределами прежних 4000 символов), ранжирует реальные источники и выбирает точный фрагмент по вопросу; перед выдачей повторно сверяет редакцию и полный текст.

- Оригиналы сверены по существующему manifest, архивные участники — по SHA-256.
- Все 53 payload проходят текущую схему CMS; повторная подготовка детерминирована.
- Реальных описей/дел/цифровых копий фондов исходники не содержат, они не созданы.
- До выполнения R-B01 пакет готов к публикации, но не является опубликованным сайтом. После интеграции Артур проверяет поиск/ИИ и снимает новую галерею.

## Тексты и найденные стыки интерфейса

`ui-copy.json` — готовые RU/KK/EN тексты главной, четырёх входов, краткого подвала, часов и пустых состояний. При браузерном просмотре прежний UI всё ещё показывает в подвале оговорку про вымышленные материалы, старое вступление со сверкой 8 ноября и быстрые ссылки «письмо/фотография/карта» при отсутствии таких реальных дел. Это конкретные остатки R-F02, а не повод добавлять фикстуры. Готовая редакция заменяет эти тексты; настоящие изображения из manifest подключаются в R-F04.

По итогам прогона старой платформы все 53 записи публикуются через CMS API. Обнаружен и исправлен стык: ограничение JSON в 16 KiB отбрасывало допустимые 9248 русских символов истории. Коммит `1055a4b` расширяет только CMS create/edit/new-revision до 64 KiB, сохраняя схему с лимитом 10000 символов и остальные проверки. Не потерять эту правку при интеграции backend.
