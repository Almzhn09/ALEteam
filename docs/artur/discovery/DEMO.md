# Защита и воспроизведение

## Проверяемый показ: около4 минут

1. Главная: «Для вас» → настроить темы → сохранить → обновить страницу → отключить персонализацию. Указать отличие редакционной подборки от измеренной популярности. Не включать фиктивную статистику. «Продолжить чтение» включается отдельно; отключение удаляет3 сохранённых ID.
2. Каталог: историческое имя → включить расширение → оставить период/тип/номер фонда → выключить расширение. Показать неизменные нули/буквы шифра. Неоднозначный Алтай требует уточнения.
3. Документ: реквизиты/разрешённая копия → выдержки и термины → сравнить с оригиналом → связанные материалы → раскрыть реальную причину/источник. Объяснение извлекает цитаты, не выдаёт себя за универсальное понимание произвольного скана. При закрытой копии текста нет.
4. История места: источник/хронология/месяц без придуманного1-го числа; годовой фильтр; отсутствие координат не мешает. У ссылки на исходный материал интерфейс сохраняет выбранный язык.
5. Каталог/место: следить → вход с возвратом → кабинет. Первоначальные материалы не приходят как новые. Опубликовать подходящую **синтетическую** новую запись вторым тестовым сотрудником, worker → уведомление; повтор worker → всё ещё одно; отписка → исчезновение подписки/уведомления.
6. ИИ: «Хочу исследовать школы Риддера после1940» → шаги исследования → кнопка каталога с1941. Это прежний помощник, а не второй чат. Затем неизвестный вопрос → честный отказ.
7. Необязательная помощь: открыть заметной кнопкой → пропустить/Escape → повторить; тема/увеличение текста доступны независимо. Показать360px/150% и светлую/тёмную тему.

Реальный автоматический показ — [видео и снимки](proof/README.md). Исторические утверждения учебных фикстур полностью вымышлены и помечены ДЕМО; нельзя рассказывать их как архивные открытия. Видео без аудио, показывает настоящий Chromium/API/БД, не монтаж моков.

## Запуск приёмки

`npm ci`, `npm run db:generate`, `npm run typecheck`, `npm test`, `npm run i18n:check`, `npm run sources:verify`, `npm run evaluate:discovery`, `npm run build`.

Для HTTP/browser задач задать **отдельную** `TEST_DATABASE_URL`, имя БД заканчивается `_test`, и отдельный `FILE_STORAGE_ROOT`. Тесты меняют/очищают только такую БД. `npm run test:discovery`, `npm run test:uploads`, `npm run test:semantic`, `npm run test:cms-assistant`, `npm run test:release`, `npm run check:display`, `npm run check:team-ui`. Последний сам мигрирует/очищает тестовые записи/создаёт временного администратора/запускает production build и браузерные сценарии. Рабочая БД/секреты из чужого .env не нужны. Для Chromium Linux — `CHROMIUM_PATH=/usr/bin/chromium`; Windows/Edge сохранён у отдельных исходных e2e-скриптов. Настоящая запись включается только при заданном `FFMPEG_PATH`; ffmpeg должен быть уже установлен.

`TEAM_UI_CHECKS=discovery` повторяет только новый путь; по умолчанию full-tz,discovery,visual-matrix. Ошибки/axe/геометрия дают ненулевой exit code. `.local/team-ui` содержит приватные серверные логи и публичные синтетические доказательства; не публиковать весь каталог/секретные env автоматически.

Сборка Docker: штатные runtime/tools из Dockerfile одной версии, `node tests/deploy.mjs` — только уникальные временные Compose проекты. Команда проверяет отказ опасного restore, карантин/мастера/превью, роли/редакции/факты/даты/подписки и точные bytes после восстановления. Публичный домен и production HTTPS здесь не проверяются.

## Измерение скорости

Lighthouse — отдельный инструмент, не runtime зависимость приложения. Для воспроизведения установить **локально проекту**: `npm install --prefix .local/lighthouse-tools --no-audit --no-fund --save-exact lighthouse@13.6.0`, затем `npm run check:performance` с той же отдельной `_test` БД и уже выполненной сборкой. Скрипт запускает свой сервер и6 измерений (главная/каталог/документ × mobile/desktop), сохраняет JSON/HTML и параметры throttling, считает performance<80 неуспехом. Это единичные локальные наблюдения на явно указанном синтетическом корпусе, не производственный SLA.

## Реальные источники: путь редактора

1. Проверить [31 кандидат](../../../data/artur/discovery/showcase-review.json) и [разночтения](SOURCE-REVIEW.md). Отдельно права на метаданные и копии; S06 не содержит цены.
2. `/admin/source-drafts`: dry-run с явным сопоставлением sourceKey/slug/Branch → отчёт → commit в DRAFT → штатные review/approval/publication другой учётной записью. Backend API описан в `docs/discovery/SOURCE-ADAPTER.md`; в существующей CMS UI можно проверять и публиковать созданные черновики.
3. После публикации получить текущие SourceRef и подготовить `prepare-artur-facts.ts --sources ... --places ... --out ...`. Ключи источников не UUID. Сначала PLACE, после их независимой проверки — ALIAS/HISTORY; изменённый родитель обнуляет зависимую проверку.
4. Предпросмотр XLSB — по [реальным колонкам](../../../data/artur/discovery/fund-preview-mappings.json); сверить буквальные номера/повторы/исторические названия. В таблицах нет описей/дел/документов, поэтому фондовый preview не проходит document staging. Газетные1466 строки не равны1466 оцифрованным документам.
5. Подтвердить контакты/график/языки, затем повторить публичный путь и отрицательные проверки. Машинный тест не подписывает решение архива и не заменяет носителя языка.
