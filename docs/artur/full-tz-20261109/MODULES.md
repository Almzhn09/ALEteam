# TZ-A06/A07/A08 — подготовленные границы интеграции

Модули TypeScript без внешней LLM; проверка `npm test`. CMS подключена к приложению (см. ниже); структурный поиск и аналитика ещё требуют соответствующих API. Это не полная приёмка ТЗ.

- `cms-knowledge.ts`: работающий адаптер к опубликованным редакциям CMS, описан ниже.
- `archive-search-intent.ts`: извлекает PHOTO, подтверждённый вариант названия города и десятилетие из RU/KK/EN. «Фотографии Усть-Каменогорска 1960-х» даёт PHOTO / ust-kamenogorsk / 1960–1969. Это правила, не измерение обученной семантической модели. Неизвестному месту не придумываются координаты. Добавлены строгие до/после, включительный диапазон и просьба уточнить противоречивые периоды; похожие подстроки (photosynthesis/фотосинтез) не считаются фотографиями. Окончательные ID мест задаёт B03, фильтры подключает B04. Нет поддержки произвольной географии/неоднозначных периодов; фиксированные тесты не доказывают полный смысловой поиск.
- `site-quality.ts`: отчёт по переданным агрегатам, а не сбор посетителей. Группы меньше 5 подавлены. Порог доли пустых поисков 30% — проектный, не согласованный с архивом. Вывод содержит период/основание/ответственного и requiresHumanReview. Идентификация людей и исходные поисковые строки не передаются. Само формирование рекомендаций — правила статистики. Опциональный quality-topic.ts распознаёт тему вопроса обученным локальным кандидатом, выдаёт только ID из фиксированного списка без сохранения исходного текста; это не генерация рекомендаций моделью и не сбор событий. Неизвестные темы, низкая уверенность и явные идентификаторы не включаются. Подключение/основания сбора согласует B10 с архивом. События и авторизацию предоставляет B10; до него A08 не закрывается.

Пример аналитики **синтетический**: catalog, 1–8 ноября, 20 поисков / 8 пустых / 2 страницы требуют проверки → проверить поиск/справку и передать редактору устаревшие страницы. Это не измеренная посещаемость сайта. Набор unit проверяет этот пример, подавление малых групп и невозможные счётчики.

## Манифест и реальные файлы (A04/A10)

`migration-audit.ts` проверяет строгий предложенный формат (не импортирует в БД), родительские связи филиал→фонд→опись→дело→документ, уникальность номеров внутри родителя, sourceId, права и разделение карточки/копии. Сравнение экспортов учитывает номера как строки, оригинальный язык, связи и SHA-256, а не порядок массивов. Неподтверждённая публикация/открытый закрытый файл — ошибка.

`migration-files.ts` читает только файлы явно выбранного корня по отдельной таблице id→относительный путь: запрещает выход/ссылку наружу, проверяет фактический размер, ограничение 128 MiB на файл, начальную сигнатуру MIME и SHA-256. Это проверка целостности/сигнатуры, **не** антивирус, полный парсер PDF/TIFF и не доказательство прав. Формат и больший лимит согласуются с B07/B08.

```sh
npm run audit:migration -- --manifest data/artur/migration-fixture.json
npm run audit:migration -- --manifest export.json --compare roundtrip.json
npm run audit:migration -- --manifest export.json --files-root /path/to/export --locations locations.json
```

Код завершения 0 — проверено; 1 — несоответствие; 2 — ошибка аргументов/чтения. Без files-root проверяется только декларация, bytesVerified=false. В демонстрационном migration-fixture.json нулевой SHA/42 байта — **заглушка формата**, не хеш настоящего файла; для проверки байтов нужен реальный разрешённый манифест. Тесты отдельно сверяют пять существующих PNG с их настоящими хешами из data/scans/manifest.json.

## Подключение к foundation 7cfed5c

К фактическим таблицам ContentItem/ContentRevision подключён cms-knowledge.ts; он не выдумывает отсутствующие в схеме assistantAllowed/translationStatus, а проверяет реальный цикл PUBLISHED, независимого reviewer, locale и публичность филиала. Опубликованный plain-text CMS payload рассматривается как публичный материал для цитирования, SETTING исключён. Это функциональная политика прототипа; окончательный состав разрешённых полей/материалов утверждает архив. [Реальная интеграция, границы и проверка](CMS-INTEGRATION.md).
