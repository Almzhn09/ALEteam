## Источники помощника

POST /api/assistant принимает дополнительное необязательное `locale: ru|kk|en`. Браузер отправляет выбранный язык интерфейса. Для старых клиентов сохраняется прежнее определение RU/KK по вопросу; EN выбирается явно. Ответ дополняется источниками kind=cms и locale, остальные поля/старые источники совместимы.

cms-knowledge.ts читает только актуальную PUBLISHED-редакцию выбранного языка, с reviewerId другого сотрудника, исключая SETTING и материалы закрытого филиала. Структурированные контакты BRANCH_PROFILE включаются из утверждённого payload; координаты/контакты не выводятся из весов или догадки. Проверяются payload и подозрительные инструкции. Private reasons, author/reviewer IDs, внутренние заметки, account data и массивы файлов/связанных документов не отправляются в ответ и не расширяются в текст.

Поиск ограничен восемью значимыми префиксами слов, обязательными для совпадения, и 12 кандидатами; отбирается максимум 3 источника. Общие слова вроде «документы» не перехватывают конкретный запрос каталога. Это ограниченный лексический отбор, не обещание полноценного смыслового ранжирования. Короткие явные уточнения RU/KK/EN могут использовать только последние безопасные пользовательские вопросы в окне 6 сообщений; переданные клиентом ответы assistant не являются источниками. Другой язык не подставляется вместо отсутствующего перевода.

Перед возвратом источники заново проверяются по статусу, видимости филиала, языку, updatedAt, названию и тексту. Изменённая/снятая во время запроса публикация даёт 503 ASSISTANT_SOURCE_CHANGED. Новые вопросы не используют старую редакцию; уже доставленный пользователю текст не может быть отозван задним числом. Сохранённый assistant history не используется как источник фактов.

CMS-текст цитируется локально и дословно, mode=retrieval; он не посылается внешней LLM и не добавляется в обучение. Локальная модель прежнего каталога продолжает работать отдельно. При явно настроенном ASSISTANT_SERVICE_URL прежний внешний режим не получает новый корпус CMS; его ссылки на неизвестные CMS-ID не принимаются.

Источники CMS ссылаются на `/api/content/<slug>?locale=<locale>`, где доступен текущий публичный материал. Полноценная публичная страница контента — часть работы Алинура. В интерфейсе ссылки уже открываются, недоверенные href из sessionStorage ограничены известным локальным endpoint. Технический revision ID остаётся в metadata ответа, а не в видимой цитате.

Дополнительно старый документный корпус теперь требует isPublic=true **и** allowDigitalCopy=true: прежняя description могла содержать текст учебной копии. Публичная карточка с закрытой копией остаётся доступной через каталог, но её текст не цитируется, пока нет отдельного утверждённого поля публичной аннотации. Это консервативное ограничение, не закрытие всей карточки.

## Английская локальная ветка

При ASSISTANT_MODE=local-model и locale=en сначала ищутся опубликованные EN-источники CMS. При их отсутствии english-dialog.ts использует реально обученный кандидат training/full-tz/models/query-model.json, порог 0.8 и только известные намерения: помощь по сайту, избранное, комментарии, вход, файлы, уведомления, термины и источники. Текст ответов — авторские английские справки, а не свободная речь модели. Источник содержит дословный English-раздел и titleEn в публичном /api/guides/:id. Ссылки и заголовки источников имеют язык en.

Есть короткие уточнения по последним безопасным user-репликам. Новые неизвестные темы сбрасывают контекст; assistant-проза клиента игнорируется. Неизвестные исторические факты, отсутствующие переводы и запросы секретов получают честное отсутствие ответа. Внешний API не используется. Старые RU/KK-веса не заменены, новые английские веса используются в ограниченной ветке, не как универсальная LLM. Результат общего test кандидата остаётся 714/817; дополнительные регрессии не превращают его в независимый языковой бенчмарк.

Это backend/API-поддержка EN, не готовая английская локализация всего интерфейса/каталога. Английская и казахская редактура человеком, CMS-контекст вне коротких явных уточнений и независимый набор качества остаются работой A05.

## Контент-пакет без автоматической публикации

`npm run content:artur:export` преобразует data/artur/content-pack.json в data/artur/cms-draft-package.json: 7 материалов × RU/KK/EN = 21 черновик с человекочитаемыми названиями. Создание совместимо с POST /admin/content и POST /admin/content/:id/revisions, без status/reviewerId или команд перехода. Контакты без подтверждённых координат остаются FAQ-черновиком, а не выдуманным BRANCH_PROFILE. Неизвестные официальные материалы и права не заполнены догадками.

Реальный импорт 21 черновика проверен только на отдельной тестовой БД; после тестов фикстуры удалены. Экспортный пакет не публиковался на рабочем стенде. Перед реальным применением нужны назначенный сотрудник, независимое ревью переводов/прав и обычный редакционный путь CMS.

## Воспроизведение

```sh
npm ci
npm run db:generate
npm test
npm run typecheck
npm run i18n:check
npm run build
# Только отдельная тестовая БД, имя заканчивается на _test:
npm run test:integration
npm run test:cms
CHROMIUM_PATH=/usr/bin/chromium npm run test:cms-assistant
npm run test:release
```

test:cms-assistant создаёт собственные тестовые аккаунты/материалы, проверяет реальные запросы и браузер; пароль генерируется, не пишется в отчёт. Старый test:cms очищает CMS-фикстуры в выделенной БД, поэтому не запускать на данных пользователя. Для CI добавлен отдельный прогон и сохранение .local/cms-assistant. Запуск GitHub Actions не объявляется успешным только из-за локальных результатов.
