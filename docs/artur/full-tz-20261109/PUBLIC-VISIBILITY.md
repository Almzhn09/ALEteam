# R-A06 — единый отзыв видимости публичного филиала

На исходной production-сборке a11130e (код приложения как в 14b6fb7) воспроизведено: после `ArchiveBranch.isPublic=false` каталог продолжал возвращать семь его опубликованных карточек. Помощник уже скрывал информационные CMS-материалы филиала, но другие публичные поверхности проверяли только флаг документа. Новый сквозной тест сначала дал 32 PASS / 1 FAIL с ожидаемым 0 и фактическим 7. Ошибка тестовой подготовки slug исправлена до этого воспроизведения и не выдаётся за дефект продукта.

`public-visibility.ts` задаёт единое серверное условие: опубликованный документ, не удалённый, его фонд относится к видимому филиалу либо является прежним общим фондом без филиала. SQL-часть использует постоянные алиасы и связанные параметры, не пользовательские SQL-фрагменты. Для CMS проверяется видимость филиала у всех типов материалов, внутренний ARCHIVE_DOCUMENT не превращается в информационную страницу. Служебное чтение по правам/областям продолжает действовать отдельно.

После скрытия филиала:

- каталог/счётчик и список фондов не показывают его записи;
- карточка, комментарии карточки, похожие материалы, файл и OCR дают 404;
- избранное, собственные комментарии и уведомления отфильтрованы; повторное добавление скрытой карточки и жалоба на её комментарий дают 404;
- его CMS-публикации не доступны публично; ссылки documentIds/fileIds/contentIds/exhibitIds в других публикациях отфильтровываются при чтении;
- нельзя опубликовать новую ссылку на уже недоступный источник;
- лексический/структурный корпус помощника не включает скрытые записи; повторная проверка ранее выбранного источника прекращает его использование;
- похожие материалы не индексируют описания ограниченных цифровых копий и удалённые/скрытые карточки.

Данные и их история не удаляются: скрытие филиала — переключатель публичной доступности. Повторное открытие филиала снова допускает всё ещё опубликованные материалы. Архивирование редакции, отзыв разрешения копии и корзина остаются самостоятельными механизмами. Уже доставленный пользователю ответ/скачанный файл нельзя отозвать с его устройства; последующие запросы проверяют актуальное состояние, ответы остаются no-store.

Прежние демофонды с branchId=null сохраняют доступность по собственному isPublic документа; миграция не выдумывает им архивный филиал. Сотруднический просмотр/модерация не является публичным endpoint и сохраняет свои отдельные полномочия. Окончательное правило архива по наследованию видимости требует человеческого согласования; это консервативная техническая политика прототипа.

## Проверка

В `test:semantic` собственные согласованные RU/KK/EN-карточки публикуются через реальные API, к одной временно привязывается существующий оригинальный PNG с проверенным OCR. До скрытия подтверждаются доступные PNG/OCR/карточка/CMS/избранное/уведомление. Затем проверяются реальные HTTP-отказы, списки и снимок источника помощника. Файл, филиал и собственные тестовые связи восстанавливаются в finally. Работа идёт только в отдельной `_test` БД, созданной runner, без данных пользователя.

Положительные тесты CMS/каталога теперь явно создают **публичные** филиалы. Проверка переключателя профиля по-прежнему сначала скрывает его, проверяет 404, открывает, проверяет 200 и снова закрывает с 404. Публичность положительных фикстур не заменяет отрицательную проверку и не ослабляет её. Проверка ссылок выставки возвращает нужный филиал в открытое состояние перед своим отдельным положительным сценарием.

Команды: `npm test`, `npm run typecheck`, `npm run i18n:check`, `npm run build`, затем все шесть существующих HTTP/браузерных прогонов. Доказательства baseline/после исправления сохраняются отдельно после завершения фактического прогона. Большой корпус/публичный HTTPS и независимая приёмка не следуют из этого теста.
