# TZ-A04/A05/A06/A07 — поиск по опубликованному многоязычному каталогу

Интегрирована ветка backend/alimzhan-catalog-workflow, b2c2cbe; merge-коммит 3a25cf6. [Контракт каталога](../../catalog/API.md). До запуска необходима миграция 202611090004 и генерация Prisma. Модель с нуля не заменена внешним API, новые вопросы оценки не использовались для переобучения.

## Поведение

Запрос «Фотографии Усть-Каменогорска 1960-х» преобразуется в PHOTO, подтверждённый вариант названия места и период 1960–1969. Поддержаны RU/KK/EN, полные годы, десятилетия, строгие до/после и включительные диапазоны. Пересечение периода записи с запросом определяется общим каталогом: запись 1969–1971 также относится к запросу за 1970 год. Противоречивый период, исключённые или несколько типов вызывают уточнение. Информационный запрос без явных каталожных условий, например Library hours, сначала получает утверждённый ответ CMS; конкретные условия поиска направляются в каталог.

Номера фонда/описи/дела выделяются строками: `0007`, `0001`, `0003/А`. Они не превращаются в числа, годы или нормализованные Unicode-аналоги. Шифр DEMO разбирается отдельно и проверяется точно, хотя публичный API допускает подстрочный фильтр. Известное место не выводится из случайного упоминания в документе: используется опубликованное поле locality выбранного языка.

Словарь data/artur/semantic-dictionary.json содержит одну ограниченную группу названий города. RU/KK сверены с аудитом официального сайта; английские транслитерации — рабочие алиасы проекта и требуют просмотра архивом. Географические координаты или исторические связи из них не придумываются. Неизвестное место/предмет остаётся буквальным поисковым условием, а не превращается в известный город.

Пять известных предметных тем нормализуются к языку опубликованной записи. В локальном режиме собственный кандидат дополнительно маршрутизирует конечный набор обученных обозначений (например, railroad → станция → station); это действительно меняет q, а не только подпись режима. Тип/период/номера/город определяются правилами. Неизвестный ввод не заменяется предположением модели. Ответ — выдержка из текущей публикации, не свободная историческая генерация.

## Код и источник данных

- semantic-catalog-plan.ts: типизированный CatalogFilters, язык, неоднозначность, предметная нормализация и короткие уточнения по периоду. История ограничена последними 6 пользовательскими/ассистентскими сообщениями API; для контекста используются только безопасные user-реплики. Уточнение «and after 1970» заменяет прежний период, сохраняя тип/место/тему, а не добавляет второй диапазон. Assistant-проза клиента не является источником.
- semantic-catalog.ts: **внутрипроцессный** вызов общего documentList, без сетевого запроса к самому себе и без дублирования SQL/прав каталога. Проверяются возможные написания locality, до 5 записей на вариант (не более 15 кандидатов), затем доступная публичная карточка. Ранжирование ограниченное: совпадение темы в заголовке/тексте, год, ID; максимум 3 цитаты. Это не векторный поиск по неограниченному архиву.
- Источник — DocumentTranslation нужного языка и доступная Document, а не основной RU-текст для всех языков. Удалённая/снятая карточка, отсутствующий перевод или неверная ссылка на опубликованную редакцию не цитируются. Изменение основной RU-редакции отзывает прежние переводы по механизму Алимжана.
- До ответа повторно проверяются доступность, разрешение копии, язык, публикация, цитируемый текст, права и revision ID. Отозванный/изменённый источник приводит к отказу повторной проверки, не к старому ответу из кэша. Старые непроверенные RU-снимки допускаются только при открытой копии и совпадении основного текста с публичной проекцией; исторический reviewer не выдумывается.
- Для новой согласованной карточки с закрытой копией показываются лишь название/шифр/период и явная пометка ограничения. Description закрытой копии, file/OCR bytes, private notes и служебные причины не цитируются и не раскрываются. Архивист всё равно должен определить окончательный состав публичных полей.

Ответ POST /api/assistant дополнен необязательным catalogQuery с интерпретированными фильтрами. Ссылки document для kk/en указывают на `/api/documents/:id?locale=...`, чтобы существующая RU-страница не подставляла другой язык. Для ru сохраняется обычная страница карточки. Полные формы расширенного поиска и страницы EN/KK — область Алинура; нельзя обещать, что старый /catalog уже применяет все новые URL-поля.

Старые API-клиенты без locale сохраняют RU-проекцию документов, включая вопросы на казахском к старому русскому демокорпусу. Новые клиенты должны передавать locale явно: тогда перевод не подменяется. Основной корпус и каталожная информация CMS разделены: внутренний ARCHIVE_DOCUMENT не читается как информационный материал с payload.body.

## Контрольный набор и проверка

Фиксированы 27 авторских случаев (исходные 25 и два дополнительных уточнения исключённых/нескольких типов) в tests/fixtures/semantic-catalog.json; точных совпадений с обеими train-выборками нет. Создаются только собственные явно демонстрационные записи, включая другой город, другой тип, закрытую копию, черновик, отсутствующий перевод и источник с инструкцией атаки. Для ранней и новой цепочки используется одна текущая тестовая БД. Это набор приёмки разработчика, не независимый бенчмарк понимания языка и не реальный архивный объём.

Сравнение — прежний legacy RU retrieval против новой связки переводов/фильтров/предметного маршрутизатора. Оно не измеряет только нейросеть. Оцениваются точные множества ожидаемых источников и средний recall@3 по непустым запросам. Результаты генерируются из полного фактического прогона, не из плана; неполный прогон не принимается за успех.

Фактический текущий прогон: точные множества источников **8/27 → 27/27**, непустые запросы **1/20 → 20/20**, средний recall@3 **0.1167 → 1.0**. Исходные 25 случаев: **6/25 → 25/25**; два позднее добавленных случая уточнения типа проверены отдельно в том же наборе. После интеграции RU **10/10**, KK **5/5**, EN **12/12**. Негативные случаи входят в общий счёт, поэтому он не заменяет результат непустых запросов. [Полные строки и before/after](semantic-proof/quality.json).

Пароли/куки не сохраняются в отчётах. CI выполняет этот прогон и сохраняет .local/semantic-catalog.
