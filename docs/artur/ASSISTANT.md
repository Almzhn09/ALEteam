# I01–I04 — помощник по источникам

## Сценарии и режимы

Помощник ищет материалы о библиотеке, школе, музее, площади и железной дороге, уточняет период/точный DEMO-шифр, объясняет фонд/шифр и правила интерфейса. Не оформляет государственные услуги, не выдаёт юридические гарантии и не ищет закрытые персональные сведения. Сведения об официальном архиве не выдумываются.

**По умолчанию ASSISTANT_MODE=retrieval:** локальный поиск PostgreSQL и ответы из точных фрагментов. Он работает без LLM и ключей, явно возвращает mode=retrieval. Это поиск с подготовленными ответами, а не генеративная нейросеть. Пользовательский интерфейс должен показывать режим.

**ASSISTANT_MODE=llm:** OpenAI Chat Completions помогает выбрать до трёх релевантных дословных фрагментов. Нужны ARCHIVE_LLM_API_KEY и ARCHIVE_LLM_MODEL, доступ к api.openai.com и заранее установленный бюджет у провайдера. Ключ вводить безопасно в настройках окружения, не в чат/Git. Модель указывается явно; действующие цены и доступность конкретной модели проверяются при подключении. Без конфигурации или при сбое возвращается 503; скрытой подмены LLM режимом поиска нет. Реальный вызов провайдера пока не проверен.

LLM получает вопрос и до пяти публичных фрагментов по 4000 символов. Не получает сессии, email, настройки, ключи или всю историю чата. Возвращает JSON со sourceId/quote; сервер проверяет ID, точное вхождение цитаты и собирает ответ самостоятельно. Свободные утверждения модели не выводятся. Таким образом неподтверждённый текст, выдуманная ссылка и попытка вернуть конфигурацию приводят к ошибке, а не к публикации ответа.

## Корпус и поиск

20 материалов в data/demo-corpus.json — оригинальные вымышленные примеры CC0-1.0. Происхождение и SHA-256 каждого текста проверяются evaluate:artur. Первые пять имеют генерируемые PDF-демолисты. Есть четыре отдельные авторские справки ALEteam, доступные через `/api/guides`. Историческая достоверность демоматериалов не заявляется; любой ответ с ними получает предупреждение ДЕМО.

Поиск использует русский полнотекстовый индекс и небольшой явный словарь тем на русском/казахском. Для неоднозначной русской морфологии добавлен поиск по проверенным корням заголовков. Это тематическое сопоставление, не полноценная казахская морфология и не смысловые embeddings. Неподдержанный запрос получает «В доступных источниках ответа нет». Личные имена и подробные биографические запросы не поддерживаются демонстрационным корпусом.

Вопросы на казахском получают короткие казахские сообщения; цитаты сохраняют язык оригинала. Перевод цитат моделью не выполняется. Языковой аудит носителем требуется до публичного показа. История валидируется API для совместимости, но не используется для неявного разрешения местоимений: вопрос следует формулировать самостоятельно.

## Ограничения и защита

Только публичные документы участвуют в извлечении; доступность ссылок перепроверяется перед ответом. Источники с подозрительными инструкциями исключаются. Инструкции в вопросе не меняют системные правила. HTML не исполняется. Простые эвристики не дают полной защиты от всех смысловых атак, поэтому сервер разрешает показывать только исходные цитаты и собственные фиксированные подписи.

API ограничивает запрос: 1000 символов вопрос, до 6 сообщений истории по 1000, 10 запросов/час на пользователя, 100/сутки на весь стенд. Для LLM установлены 500 output tokens, таймаут 8 секунд, запрет redirect, ограничение ответа 32 KiB. Входящий клиент не выбирает модель, URL, system prompt или бюджет. Логи не содержат вопросов, цитат, cookie и ключей. В облаке fetch использует предусмотренный proxy/CA через стартовую команду Node.

У существования источника есть предел: оно не доказывает, что цитата отвечает на вопрос. Качество нужно повторно проверять на новом реальном корпусе. Подготовленные 20 вопросов, негативные unit/HTTP-тесты и случаи подмены источников описаны в отчёте; это не проверка реальной LLM и не доказательство полноты защиты.
