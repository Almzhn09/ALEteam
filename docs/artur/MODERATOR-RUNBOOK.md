# Работа с очередью на хакатоне

Владелец модерации по распределению задач — **Артур**. Алимжан отвечает за доступ и работоспособность API; Алинур — за интерфейс очереди. Назначение в плане не означает, что команда уже провела репетицию или утвердила публичные сроки ответа.

1. Перед показом открыть `/moderation`, проверить роль MODERATOR и разобрать PENDING/жалобы. Обычному автору кабинет и API недоступны.
2. Проверить исходный текст и документ, а для цитаты — её необходимость и контекст. Явные нарушения оставлять отклонёнными; неоднозначный случай не публиковать ради пустой очереди.
3. Выбрать решение, указать содержательную причину и сохранить. При конфликте версии перечитать запись; не перетирать чужое решение.
4. Жалоба сама по себе не доказывает нарушение. При скрытии сохранить причину. Для исправления ошибки открыть вкладку скрытых/отклонённых и восстановить с причиной.
5. Проверить публичный список и журнал. В нём должны остаться переходы состояний, время и модератор; удалять историю для презентации нельзя.
6. При сбое дополнительного фильтра или неизвестной конфигурации использовать очередь. Не отключать лимиты и не разрешать клиенту передавать статус публикации.

Проверка этого пути браузером автоматизирована в `npm run test:release` на отдельной тестовой БД. Пароли демонстрационных пользователей находятся в приватном окружении и не включаются в скриншоты или документы. Общая репетиция и ручная языковая проверка остаются действиями людей.
