# N-B01/B02 — готовый адаптер CMS-черновиков

Основа `1592296`, контракт `8539ad2`. Копии исходных файлов остаются в sources/archive-20261110; CLI `node scripts/verify-archive-sources.mjs` проверил 9 оригиналов, 25 извлечений, 3 связанных файла. HTTP-адаптер использует подготовленные immutable JSON и SHA оригинала из реестра, не загружает произвольные пути/URL и не запускает файлы.

## Реальные маршруты

Все `/api/admin/source-drafts`, активная staff-сессия; изменения same-origin. GET коллекции требует глобального content.write. POST stage/GET detail/commit перепроверяют content.write в области всех строк; филиальный пакет дополнительно branches.manage. Чужой автор не читает пакет без глобального audit.read. Создание новых филиалов требует глобальных прав; mapping на существующий филиал проверяется по его области.

GET `/api/admin/source-drafts` → package, 18 cms-ключей, 13 branch-ключей, sourceHash/locale и флаги исходных проблем. Тела источников в этом списке не выдаются. Совмещение RU/KK требует явного mapping, а не догадки о правильности перевода.

POST stage, пример одной языковой пары:

```json
{"package":"archive-20261110","mode":"cms","mappings":[
 {"sourceKey":"calendar-2026-ru","slug":"archive-calendar-2026"},
 {"sourceKey":"calendar-2026-kk","slug":"archive-calendar-2026"}
]}
```

201 `{item:{id,status:"READY",manifest,report,...}}`. Только staging; ContentItem/Revision/Branch ещё не созданы. Report содержит create/unchanged/conflict и фиксированный код. В stage максимум 50 источников/64 KiB сопоставлений; реальные тексты берутся по sourceKey из подготовленного пакета. Неизвестные поля, одинаковый sourceKey, повтор locale одной страницы и несовместимые branch/kind внутри slug запрещены.

POST `/api/admin/source-drafts/:id/commit` `{}` → `{item:{status:"COMMITTED",...}}`. Одна транзакция под advisory lock, повторная проверка актуальной БД. Используются общие createCmsDraft/appendCmsDraft, те же payload/checkPayload и штатные ContentRevision DRAFT. Ни IN_REVIEW, ни APPROVED/PUBLISHED не устанавливаются. Адаптер не создаёт архивных документов/описей/дел по названиям фондов.

Два языка с одинаковым slug становятся двумя редакциями одной страницы. Исходные sourceKey/sourceId/request, исходные контакты/проблемы, SHA оригинала и requestHash сохраняются в SourceDraftBinding. Повтор COMMITTED или идентичного пакета не создаёт дубли. Ручная правка связанной редакции, занятый чужой slug, изменившееся сопоставление/пакет дают конфликт; перезаписи нет. Для обновления/редакторского объединения источника нужен отдельный контролируемый процесс, автоматического исправления не предлагается.

## Филиалы без вымышленных данных

POST stage `{package:"archive-20261110",mode:"branches",mappings:[{sourceKey:"S01-Книга-11",slug:"branch-markakol"}]}`. Для существующего филиала передать его branchId, для нового — не передавать: создаётся стабильное opaque ID, isPublic=false, isDemo=false, и профиль DRAFT. Повтор sourceKey устойчив. SourceDraftBinding хранит полную исходную запись; источник — лист «Книга» и строка, лист VPN не переносится.

BRANCH_PROFILE теперь требует адрес; телефон/email/график/координаты могут отсутствовать. Если указана одна координата, нужна вторая; диапазоны сохранены. Публичный профиль имеет mapAvailable=false без координат либо при неутверждённых координатах. contactReview содержит address/phone/email/hours/coordinates со значениями verified/unverified/missing/needs_confirmation. Старые полные профили совместимы.

У Марқакөл отсутствующий телефон остаётся отсутствующим. alimvko.gov.kz / akimvko.qov.kz не исправляются автоматически: исходник сохранён и email needs_confirmation. Невалидный синтаксически email не попадает в поле email, но остаётся в original пакета. Новых часов/EN/координат нет. Наличие источника и создание DRAFT не подтверждают актуальность/права; независимое CMS-согласование и открытие филиала по-прежнему обязательны.

Для Алинура: текстовую карточку показывать без карты, неизвестный контакт не превращать в активный проверенный mailto/tel; flags нужны для доступного состояния. Для Артура: при grounding профилей учитывать contactReview, не объявлять неподтверждённые поля проверенными контактами. Engine-файлы Артура и src/lib не менялись.

## Проверено

`npm run test:discovery`: 4 HTTP-сценария на отдельной `_test` БД. Все 18 реальных подготовленных запросов → 11 явно сопоставленных страниц/18 DRAFT-редакций; все 13 филиалов → закрытые строки/профили. Повтор, конфликт ручной правки, область другого филиала, запрет посетителю, настоящий синтетический опубликованный профиль без координат и его отзыв проверены. Реальные исходные материалы этим тестом не публиковались. Основные БД/файлы/ветки участников не изменялись.

Это проверка адаптера, не приёмка содержания/языка и не завершение N-A02. Другие COL-маршруты реализуются следующими коммитами по CONTRACT-v1.md.
