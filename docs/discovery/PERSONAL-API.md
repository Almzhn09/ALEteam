# COL-B05 — интересы, рекомендации и тематические подписки

Работающий transport, все пути начинаются `/api`. Новые уведомления отделены от существующих уведомлений о комментариях. Данные пользователя берутся из сессии; userId в запросе не принимается.

- GET/PUT `/me/interests`. PUT `{topicIds:[],personalizationEnabled:false,historyEnabled:false}`. Только проверенные темы; максимум20. Настройки по умолчанию выключены. `historyEnabled:true` →503 HISTORY_NOT_CONFIGURED, никакого неявного сбора истории.
- GET `/discovery/home?locale=ru&limit=5`. `recommended.mode=editorial|interests`, `engine=baseline`; только проверенные EDITORIAL и текущие открытые материалы. Анонимный `topicIds=id,id` — явно выбранные темы. Отключённая персонализация аккаунта игнорирует этот параметр. `popular.status=unavailable,period=null`, пока нет утверждённых агрегатов. `continue.scope=browser,items=[]`: историю браузера ведёт интерфейс, сервер её не получает.
- POST `/me/topic-subscriptions` `{locale:"ru",filters:{q:"архив",type:"PHOTO"}}`, либо topicId/placeId, либо их совместное AND-условие. Только фильтры существующего каталога; locale согласован, page/pageSize/sort запрещены. Первый запрос201, повтор активной подписки200 с тем же ID. Максимум25 активных подписок.
- GET `/me/topic-subscriptions?locale=ru&limit=5&cursor=…`. DELETE `/me/topic-subscriptions/:id` — только владелец, повтор допустим. Реактивация сбрасывает baseline и прошлые уведомления.
- GET `/me/topic-notifications?locale=en&limit=5&cursor=…` → `{items,nextCursor,locale}`; выбранная локаль допускает явно обозначенный оригинал. PATCH `/:id` `{}` отмечает своё доступное уведомление прочитанным. Снятая подписка/материал/филиал исключает уведомление на следующем запросе; чужой ID404.

Публикация штатной CMS/card создаёт MaterialPublication в той же транзакции. Подписка запоминает текущую последовательность и уже совпавшие материалы; старый корпус не приходит как новый. Отдельный cursor продвигается независимо от baseline. TopicNotice уникален по подписке и материалу: повтор процесса/повторная публикация редакции не дублирует уведомление. Неподходящий язык, снятая публикация и устаревшая редакция пропускаются. Загрузка файла и DRAFT-импорт не считаются публикацией материала.

`npm run discovery:deliver` — один ограниченный проход (100 подписок ×50 событий); повтор безопасен. `npm run archive:jobs` / Docker profile workers — периодический запуск с проверкой файлов. Внешняя почта/push не подключены. На небольшом проверяемом корпусе baseline ограничен1000 карточками и1000 CMS; превышение503 DISCOVERY_CORPUS_LIMIT, старые совпадения молча не обрезаются. Проверка baseline под общей блокировкой публикации ограничена20 секундами; масштабирование требует отдельного замера/оптимизации.

Артуру: `discovery-engine-registry.ts` — статическая точка подключения rankRecommendations после передачи проверенного модуля. Сейчас используется честная редакционная основа. Сервер сверяет ID/версию результата с разрешёнными кандидатами. Модули assistant/semantic-catalog и фронтенд не менялись.

Проверено HTTP: явное отключение/выбор тем, запрет неразрешённой истории, отсутствие вымышленной популярности; baseline, повтор подписки, повтор воркера, новая редакция без дубля, original fallback уведомления, чужое чтение/отметка и отписка, отзыв источника/филиала. Данные тестов синтетические.
