# COL-B01 — опубликованный транспорт v1

Основа: `artur-full-tz-20261109@1592296`. Ветка реализации: `backend/alimzhan-discovery-v1`. Схема/DTO закреплены в `src/contracts/discovery.ts`, миграция `202611100003_discovery_contracts`. Старые маршруты/DTO не переименовываются. Последующие коммиты добавляют реализации; наличие типа **не означает готовый endpoint**.

## Решения для Алинура и Артура

- Имена маршрутов сохраняются из проекта `задачи/ТЗ-2026-11-10/Контракты.md`: `/discovery/aliases`, `/places`, `/places/:id/history`, `/documents/:id/related`, `/documents/:id/explanation`, `/discovery/home`, отдельные `/me/interests`, `/me/topic-subscriptions`, `/me/topic-notifications`.
- Каталог получает только совместимые `nameMode=literal|expanded` (по умолчанию literal) и `placeId`. Не меняются остальные AND-фильтры/сортировка/пагинация/шифры. Метаданные расширения — `nameExpansion`; неоднозначность возвращается явно, не объединяет места автоматически.
- Новые текстовые списки принимают locale; при разрешённом fallback к оригиналу возвращаются contentLocale/translationStatus=original. Старые `/content` и `/documents` по-прежнему требуют точный опубликованный язык. Неподтверждённый перевод не используется.
- ID — opaque строки; курсор связан с типом запроса/локалью/фильтрами, включает последний ID. Клиенту нельзя строить/изменять его содержимое. Списки 1–20, по умолчанию 5.
- SourceRef.revision — идентификатор опубликованной редакции либо SHA-256 разрешённой legacy-проекции; href/title назначает транспорт. Копия и её OCR проверяются отдельно от карточки, права не выдаются по URL/пути из запроса.
- Структурные факты PLACE/ALIAS/TOPIC/LINK/HISTORY/EDITORIAL хранятся в DiscoveryFact: DRAFT → VERIFIED другим сотрудником → WITHDRAWN. Это проверка связей/метаданных, не новая система публикации текстов: рассказ/событие/биография остаются в существующей CMS. Опубликованные источники и их текущая версия перепроверяются на каждом публичном чтении.
- MaterialPublication — последовательный журнал публикаций для baseline подписок. TopicNotice уникален по подписке и материалу; старые совпадения не рассылаются, повтор редакции не создаёт дубль. Отзыв проверяется перед выдачей/отметкой прочтения; старые comment notifications не заменяются.
- DiscoveryAggregate — только явно утверждённые агрегаты за период. Сбор просмотров выключен по умолчанию; отсутствие измерений — unavailable, не ноль. История пользователя не включается автоматически.

## Интерфейсы движков

`DiscoveryEngines` фиксирует expandNames/rankRelated/rankRecommendations/explainFragments/planResearch. Артур реализует чистые детерминированные модули в своей области; транспорт передаёт CandidateSnapshot/AuthorizedText **после** проверки доступа и сверяет возвращённые ID/цитаты повторно. Движок не получает Prisma, cookie, userId, файловые пути или произвольный URL.

Ранжирование может вернуть только кандидатов из входного снимка, причины — из ReasonCode, evidence — из разрешённых SourceRef. Explanation.ready требует настоящие цитаты/fragmentId; endpoint не объявит словарь/выборку цитат полным пониманием документа. Пока движок не передан, объяснение сообщает unsupported, рекомендации используют честно обозначенную редакционную основу.

Регистрация движков — отдельный статический серверный адаптер транспорта (после передачи SHA модуля Артуром), не HTTP-загрузка JavaScript и не второй ассистент. Общий assistant.ts и engine-файлы Артура этим контрактным коммитом не меняются.

## Статус первой проверки

Генерация Prisma и применение миграции проверены на выделенной `_test` БД. Основные БД/файлы/ветки участников не изменяются. Реальные географические факты/переводы/контакты не выдумываются; S01/S03/S09 сохраняют отмеченные в реестре пробелы/расхождения. Следующий коммит — dry-run/commit адаптера N-B01/B02 с полным отрицательным HTTP-сценарием и точными примерами.

## Совместимое уточнение при подключении Артуром

Для исходного требования персонализации rankRecommendations.input получил optional `historyEnabled`/`viewedKeys` (по умолчанию false/[]), ReasonCode — `history`. Без обоих разрешений история игнорируется. CandidateSnapshot получил optional `personIds`/`eventIds` — только из подтверждённых публичных серверных метаданных, не клиентских флагов. Старые вызовы без этих полей работают как прежде. Frontend должен добавить локализованный текст причины history; transport Home.mode выводить из фактически возвращённых причин, а не наличия старых просмотров. Никакого сбора истории автоматически это изменение не включает.

Для объяснений введено optional `ocr.confidence`0–1: отсутствие показателя не подменяется единицей; high-confidence unreviewed OCR может дать выдержки с предупреждением, quality=low всегда отвергается. Это машинная оценка читаемости, не подтверждение корректности фактов/чисел/прав.
