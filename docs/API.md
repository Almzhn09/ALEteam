# Контракт API v1 (для интеграции)

Base path: `/api`. JSON UTF-8. Даты — ISO 8601 UTC. Не вставлять строки ответов через `innerHTML`; JSX выводит их как текст. Все ответы API имеют `Cache-Control: no-store`.

На изменяющих запросах обязательны `Content-Type: application/json` и `Origin`, совпадающий с `BETTER_AUTH_URL`. В браузере использовать same-origin `fetch`; сессия — cookie, `credentials: 'same-origin'`. Публичный cross-origin API не включён.

## Маршруты

| Метод и путь | Доступ | Результат |
| --- | --- | --- |
| GET /health | Любой | 200 `{status:"ok",database:"ok"}` или 503 |
| GET /funds | Любой | `{items:[{id,name,description}]}`; только фонды с публичными документами |
| GET /documents | Любой | `{items,page,pageSize,total}` |
| GET /documents/:id | Любой | `{item}` с фондом и метаданными публичных файлов; закрытый/неизвестный — 404 |
| GET /documents/:id/similar | Любой | До 5 похожих публичных документов; `items:[{id,title,score,commonTerms}]`, method, candidateLimit |
| GET /files/:id | Любой | Разрешённый PDF/PNG/JPEG; путь на диске не раскрывается |
| GET /files/:id?download=1 | Любой | Attachment только при downloadable=true; иначе 404 |
| GET /files/:id/ocr | Любой | `{item:{id,text,isOcr:true,corrected:false,isDemo,engine,languages,sourceSha256}}`; только подготовленный публичный файл с совпадающим SHA-256 |
| POST /auth/sign-in/email | Любой | Better Auth: `{email,password}` → сессионная cookie |
| GET /auth/get-session | Владелец сессии | Стандартный ответ Better Auth или null |
| POST /auth/sign-out | Владелец сессии | Better Auth; сессия отзывается в БД |
| GET /me | Автор/модератор | `{item:{id,name,email,role}}` |
| GET /me/comments | Автор/модератор | Собственные комментарии и статусы, только к публичным документам |
| GET /me/favorites | Автор/модератор | Пагинация; items содержат id/title/reference/year/type/isDemo/savedAt, только собственные публичные документы |
| PUT /me/favorites/:documentId | Автор/модератор | JSON `{}`; идемпотентное сохранение публичного документа, `{added}` |
| DELETE /me/favorites/:documentId | Автор/модератор | Идемпотентно удаляет из своего списка, `{ok:true}` |
| DELETE /me/favorites | Автор/модератор | Очищает только собственный список |
| POST /me/favorites/import | Автор/модератор | `{documentIds:[...]}`: 1–100 ID; объединение со своим списком, неизвестные/закрытые пропускаются, `{added}` |
| GET /me/notifications | Автор/модератор | Пагинация и необязательный unread=1; `{items,total,unread,page,pageSize}` |
| PATCH /me/notifications/:id | Получатель | `{read:true}`; прочитано. Чужой/недоступный ID — 404 |
| PATCH /me/notifications | Автор/модератор | `{read:true}`; отметить свои доступные уведомления прочитанными |
| GET /me/notification-settings | Автор/модератор | `{item:{notifyReplies,notifyModeration}}` |
| PATCH /me/notification-settings | Автор/модератор | Обязательные boolean notifyReplies/notifyModeration; неизвестные поля запрещены |
| GET /documents/:id/comments | Любой | Только PUBLISHED, имя автора без email/сессионных данных |
| POST /documents/:id/comments | Автор/модератор | Создаёт комментарий; см. ниже |
| POST /comments/:id/reports | Автор/модератор | `{reason}` (3–500 символов); только публичный комментарий; одна жалоба от пользователя |
| GET /moderation/comments | Модератор | Очередь PENDING и комментариев с незакрытыми жалобами |
| PATCH /moderation/comments/:id | Модератор | Решение с обязательной причиной и проверкой версии |
| GET /moderation/comments/:id/history | Модератор | Пагинированный журнал решений |
| POST /assistant | Автор/модератор | Ответ из источников; генеративный режим подключается отдельно |

Произвольное изменение/удаление комментариев и endpoints изменения пользователя не реализованы. Неподдерживаемые маршруты — 404, неверный метод на auth — 405. Публичная регистрация закрыта.

## Каталог и пагинация

Общие `page=1`, `pageSize=20` (1–50), максимальная страница 10000. Каталог также принимает:

| Параметр | Значения |
| --- | --- |
| q | До 200 символов: текст или архивный шифр |
| fundId | ID фонда |
| type | LETTER / PHOTO / MAP / REPORT |
| yearFrom, yearTo | Целые годы 1–2100 включительно; начало ≤ конец |
| sort | year_asc / year_desc (по умолчанию) / title |

Неизвестные и повторяющиеся параметры каталога отклоняются. Все фильтры объединяются через AND. Пример: `GET /api/documents?q=библиотека&yearFrom=1900&yearTo=2000&type=LETTER&page=1&pageSize=10`.

Пример списка:

```json
{"items":[{"id":"demo-doc-01","title":"Демо: история библиотеки №1","description":"…","reference":"DEMO-Ф2-О1-Д1","year":1905,"type":"LETTER","fundId":"demo-fund-2","isDemo":true}],"page":1,"pageSize":10,"total":1}
```

Карточка дополнительно содержит `rights`, `sourceUrl` (может быть null), `fund`, `files:[{id,name,mimeType,size,downloadable}]`. ID стабильны, URL страницы фронтенда предлагается `/documents/:id`.

## Комментарии и решения

При POST комментария передать заголовок `Idempotency-Key: <crypto.randomUUID()>` и `{body:"Текст",parentId?:"ID опубликованного комментария"}`. Родитель должен быть опубликован и относиться к тому же документу; иначе 404. К ответам применяется тот же серверный фильтр. Текст: 1–2000 символов после trim, JSON максимум 16 KiB. Один ключ сохранять до завершения/повтора конкретной отправки. Другая отправка — новый ключ. Повтор с тем же ключом и содержимым возвращает ту же запись (200), новое создание — 201, другое содержимое/документ/parentId с тем же ключом — 409.

Ответ создания: `{item:{id,documentId,authorId,parentId,body,status,reason,moderationVersion,idempotencyKey,createdAt,updatedAt}}`. Получить собственные результаты можно в `/me/comments`; они никогда не раскрываются другим авторам. PENDING — ожидает проверки, PUBLISHED — опубликован, REJECTED — отклонён, HIDDEN — скрыт модератором. Машинные причины: CLEAN, PROFANITY, REVIEW_REQUIRED, MANUAL_DECISION. Тексты объяснений локализует фронтенд. Локальный фильтр публикует проверенные обычные сообщения, отклоняет явные нарушения и оставляет спорные случаи в PENDING. MODERATION_MODE=manual отправляет всё в очередь.

Лимиты: создание — 5/минуту на пользователя; жалобы — 10/минуту; решения — 60/минуту. Идемпотентный повтор уже сохранённого комментария не расходует лимит.

Очередь принимает `page`, `pageSize`, необязательный `status`. Передавая status, модератор получает также отклонённые/скрытые записи для восстановления. В очереди есть тело, updatedAt, имя/ID автора и незакрытые жалобы. Причина ручного решения хранится в журнале; в публичную выдачу не включается.

PATCH:

```json
{"status":"PUBLISHED","reason":"Проверено модератором","expectedUpdatedAt":"2026-11-07T12:00:00.000Z"}
```

Разрешённые цели: PUBLISHED / REJECTED / HIDDEN. `expectedUpdatedAt` взять из очереди, при 409 обновить её и повторно проверить запись. Любое решение фиксируется в журнале и закрывает текущие жалобы одной транзакцией.

## Личные списки и уведомления

Сервер берёт владельца исключительно из сессии. Параметр userId не принимается. Избранное ограничено 1000 документами на аккаунт; параллельные добавления сериализуются блокировкой строки пользователя. Операции избранного и отметок уведомлений — до 100/минуту, настройки — до 30/минуту. Гостевой список браузера переносится только отдельным действием пользователя; серверные списки в localStorage не сохраняются.

Списки /me/favorites, /me/comments и /me/notifications дополнительно возвращают ownerId текущего получателя. Клиент сравнивает его с текущей сессией и отбрасывает устаревшие ответы при смене аккаунта. Это поле ответа, а не способ выбрать владельца запроса. Изменение входа/выхода передаётся соседним вкладкам через BroadcastChannel без персональных данных; фокус окна запускает повторную проверку сессии.

Уведомление содержит только id, kind, status (для решения), createdAt, readAt, commentId, documentId. Тело комментария, email и причина модератора в него не копируются. COMMENT_REPLY создаётся после публикации ответа другому автору; собственный ответ себя не уведомляет. MODERATION_DECISION создаётся в транзакции решения. Повтор публикации/идемпотентный повтор не дублирует событие ответа. Публичность документа и комментариев проверяется при чтении: скрытый ответ или родитель исключает уведомление об ответе; решение доступно только автору соответствующего комментария. Уведомления к закрытым документам недоступны.

notifyReplies и notifyModeration по умолчанию true. Отключение подавляет новые события этого типа, не удаляет старые и не создаёт их задним числом после включения. Уведомления доступны внутри сайта; почтовой отправки нет.

## Контракт сервисов Артура

Встроенные модули работают по умолчанию; внешние сервисы являются необязательным override и вызываются только сервером. Их URL и необязательный Bearer token заданы в окружении. Разрешён HTTPS; для локальной разработки — HTTP loopback. Перенаправления запрещены. Ответ максимум 32 KiB. Режимы и реализация описаны в artur/ASSISTANT.md и artur/MODERATION.md.

**Модерация**, POST в `MODERATION_SERVICE_URL`, таймаут 3 секунды:

```json
{"text":"Комментарий"}
```

Ответ: `{status:"PUBLISHED",reason:"CLEAN",version:"rules-v1"}`, либо REJECTED + PROFANITY, либо PENDING + REVIEW_REQUIRED. Другие комбинации и сбой внешнего сервиса приводят к PENDING. При отсутствии внешнего сервиса работает встроенный фильтр. Версия: 1–80 букв/цифр/точек/дефисов/подчёркиваний. Качество словарей и обходов проверяет Артур (M01–M03).

**ИИ**, вход браузера:

```json
{"question":"Есть ли материалы о библиотеке?","history":[{"role":"user","content":"Ищу материалы"}]}
```

Вопрос: 1–1000 символов, история: до 6 сообщений по 1000 символов, только user/assistant. Модель, system prompt, URL и бюджет от клиента не принимаются. Сервер добавляет `maxOutputTokens:500` и вызывает ASSISTANT_SERVICE_URL с таймаутом 15 секунд. Сервис обязан сам применить лимит токенов и извлечь материалы из корпуса.

Ответ сервиса: `{answer:"Текст",sourceIds:["demo-doc-01"],noAnswer:false}`. Ответ без данных: `{answer:"В корпусе нет ответа.",sourceIds:[],noAnswer:true}`. Текст до 8000 символов, источников до 5. Утверждение без источников и неизвестные/закрытые ID отклоняются. Существование ID не доказывает смысловую достоверность ответа — это зона I04.

Ответ браузеру: `{answer,noAnswer,mode,sources:[{id,title,isDemo,kind,href}]}`. mode — retrieval / llm / external; kind — document / guide. Ссылки ведут на существующие `/api/documents/:id` и `/api/guides/:id`; после создания UI Алинур может отображать соответствующие страницы. Лимиты: 10 запросов/час на пользователя и 100 запросов/день на весь стенд. Сбой сервиса или отсутствие конфигурации выбранного LLM-режима — 503, неверные источники — 502. По умолчанию работает локальный retrieval без генеративной модели.

## Ошибки

Обычный API: `{error:{code,message,fields?}}`. Валидация — 400; требуется вход — 401; запрет роли/Origin — 403; не найдено — 404; конфликт версии/ключа — 409; размер — 413; формат — 415; лимит — 429 с Retry-After; недоступный сервис — 503. Поля ошибки валидации содержат только путь и код, не введённые значения. Better Auth использует свой стандартный формат `{code,message}`; фронтенду обработать обе формы.

Публичные справки: GET /api/guides возвращает items, GET /api/guides/:id — item с id/title/text. Изменение справок через API не предусмотрено.
