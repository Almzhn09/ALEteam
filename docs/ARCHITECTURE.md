# Серверная архитектура (A03)

Новая схема ролей, иерархии и CMS: [дополнение от 9 ноября](cms/ARCHITECTURE.md).

Предложение интерфейса для Алинура и Артура; согласование участниками пока не проводилось. Аудит A01 и реальный корпус A02 ещё не получены.

## Основа

Единое приложение Next.js App Router, TypeScript, PostgreSQL 16, Prisma 7 с JS-драйвером `@prisma/adapter-pg`. Вход и серверные сессии — Better Auth. Версии зависимостей закреплены в package-lock.json. Клиентский дизайн и Tailwind оставлены Алинуру.

Серверные модули находятся в `src/server`, единая точка входа API — `src/app/api/[[...path]]/route.ts`. Этот маршрут резервирует `/api`; страницы Алинура не должны использовать этот префикс. Правила доступа выполняются на сервере. CORS не открывается; запросы с изменениями требуют точного Origin из `BETTER_AUTH_URL`. Cookies управляет Better Auth: HttpOnly, SameSite, Secure на HTTPS. Роль перечитывается из БД при каждом защищённом действии, кэш сессии в cookie отключён.

Публичной регистрации пока нет: для первой серверной версии доступны подготовленные демопользователи. Недоступны также endpoints изменения профиля, пароля и роли. Производственное управление пользователями, подтверждение email и восстановление пароля требуют отдельного решения перед публичным использованием.

## Данные

- `Fund` → `Document` → `ArchiveFile`: метаданные, права доступа, явный признак демо. Файлы хранятся вне public, браузер получает только ID и безопасные метаданные.
- `User`, `Account`, `Session`, `Verification`, `RateLimit`: модели Better Auth. Пароли хешируются штатным `hashPassword` библиотеки; приложение не реализует собственную криптографию.
- `Favorite`: составной ключ userId/documentId, доступ только владельцу сессии; гостевой список переносится явно.
- `Notification` и настройки пользователя: приватные события ответа/решения без копии текста, атомарные с изменением комментария.
- `Comment` с необязательным parentId для ответов и со статусами PENDING/PUBLISHED/REJECTED/HIDDEN, результатом фильтра и ключом идемпотентности.
- `Report` хранит жалобу; `ModerationDecision` — автора решения, переход, причину и время. Решение и закрытие жалоб выполняются транзакционно, конкурентные решения защищены блокировкой строки и `expectedUpdatedAt`.
- `ApiRateLimit`: атомарные лимиты, общие для экземпляров приложения. Истёкшие записи удаляются обслуживающей командой; при недоступности БД запись и ИИ не работают.

`Document.searchVector` создаётся SQL-миграцией: русский словарь, повышенный вес заголовка, GIN-индекс. Архивный шифр ищется отдельно. SQL параметризован; сортировка выбирается только из фиксированного списка. Помощник дополнительно использует небольшой словарь русско-казахских тем; полноценная казахская морфология пока отсутствует.

## Генерация и миграции

Обычный Prisma CLI в этой облачной сети пытался загрузить native schema engine с запрещённого `binaries.prisma.sh`. Вместо отключения проверки используется JS-генератор Prisma через закреплённые `@prisma/internals` и `@prisma/client-generator-js`: `npm run db:generate`. Он использует WASM из npm-пакетов, установленных с проверкой integrity по lockfile. API этих пакетов внутренний, поэтому обновлять их нужно совместно с проверкой генерации и тестами.

`npm run db:migrate` применяет SQL-файлы по порядку через pg: advisory lock, отдельная транзакция на миграцию и SHA-256 уже применённых файлов в `ArchiveMigration`. Повторный запуск не меняет данные, изменение старой применённой миграции вызывает ошибку. Новые изменения оформлять новым каталогом с migration.sql. Не смешивать этот журнал с `prisma migrate deploy`, не использовать `db push` поверх общей БД. При смене схемы обновлять SQL и schema.prisma вместе и проверять на пустой БД.

## Границы модулей Артура

Встроенный модуль Артура выполняет локальную проверку русского/казахского мата и типовых обходов. Явные нарушения получают REJECTED, спорные цитаты/маскировки — PENDING. Возможен ручной режим. Дополнительный внешний сервис не отменяет локальное отклонение, при его сбое применяется PENDING. Правила и ограничения: artur/MODERATION.md.

Встроенный помощник ищет публичные источники и возвращает точные цитаты (mode=retrieval). Необязательный OpenAI-адаптер помогает выбирать цитаты (mode=llm); выбранные ID и цитаты проверяются сервером. Пользователь не выбирает URL/модель/бюджет, ключи и личные сведения модели не передаются. Внешний сервис можно оставить как override. Восемь авторских русско-казахских справок доступны через /api/guides; ссылки источников ведут к существующим API до появления страниц фронтенда. Детали: artur/ASSISTANT.md.

## Ограничения перед публичным запуском

Лимит входа Better Auth общий для пути (5 попыток/минуту), поскольку произвольным proxy/IP-заголовкам доверять нельзя. Для публичного сервиса настроить доверенный reverse proxy и ограничения запросов на входе. Публичный поиск не имеет индивидуального лимита; TLS, общий лимит соединений и request timeout требуется настроить на хостинге. Размер JSON проверяется сервером по фактически прочитанным байтам. Без внешнего сервиса максимальный фактический бюджет ИИ не гарантируется только лимитом API: провайдеру также нужен жёсткий бюджет.

Полноценный публичный HTTPS-стенд, проверка с участниками и внешние ключи пока отсутствуют. Опубликованную конфигурацию облачной среды этот код не изменяет.
