# План обновления электронного архива

Исходный сайт: http://e-arhiv.vko.gov.kz/ru. Команда: Алимжан, Алинур, Артур.

Сейчас создаём только план. Разработка, установка зависимостей, подключение внешних сервисов и изменение исходного сайта в эту задачу не входят. Содержимое и возможности исходного сайта ещё нужно исследовать: перечисленные ниже разделы — целевая структура, а не результат аудита.

## Цель

Подготовить к хакатону современный, удобный электронный архив: адаптивный интерфейс, поиск документов, просмотр карточек и сканов, избранное, ИИ-помощник и комментарии с серверной защитой от ненормативной лексики. Сохранить ценность архивных материалов и ясно отличать реальные источники от демонстрационных данных.

## Предлагаемая структура сайта

- Главная: заметный поиск, быстрые действия, подборки архивных материалов, краткая информация об архиве.
- Каталог: поиск по тексту и реквизитам, фильтры по периоду, типу документа и фонду, сортировка и пагинация.
- Карточка документа: название, описание, архивный шифр, дата, происхождение, права доступа, просмотр сканов и ссылка на источник.
- Избранное: сохранение материалов и возврат к ним.
- Сведения об архиве: контакты, правила доступа, помощь и доступные услуги; факты уточнить по исходному сайту.
- ИИ-помощник: поиск материалов и объяснение работы архива с проверяемыми ссылками.
- Обсуждения: комментарии к документам, жалобы и модерация.
- Кабинет модератора: очередь жалоб, скрытие/восстановление комментариев, история решений.

## Границы первой версии

**P0 — обязательно для демо:** главная, каталог с работающим поиском и фильтрами, карточка со сканом, избранное в браузере, ИИ по подготовленным источникам, комментарии с серверной модерацией, вход автора и модератора, защищённая панель модерации, адаптивность и развёрнутый стенд.

**P1 — после P0:** полноценная русская и казахская локализация, расширенная доступность, облачная синхронизация избранного, новости/подборки с управлением контентом, расширенный поиск и улучшение ИИ.

**P2 — при наличии времени:** OCR для новых сканов, поиск похожих материалов, тематическая временная шкала, уведомления, цифровые выставки.

План не предполагает доступ к государственной базе. Для демо использовать только разрешённые публичные материалы или явно помеченные демонстрационные записи. Не переносить закрытые данные, персональные сведения и чужие комментарии. Если разрешение на копирование не подтверждено, оставить ссылки или использовать собственные материалы.

## Техническая основа — предложение для старта

- Фронтенд: Next.js + TypeScript + Tailwind CSS; интерфейс и интеграция — Алинур.
- Бэкенд: серверные API Next.js + PostgreSQL + Prisma; API и модель данных — Алимжан. Выделенный сервис добавлять только при необходимости.
- ИИ: серверный вызов выбранного LLM-провайдера, поиск по подготовленному корпусу; Артур отвечает за логику и качество. Секретный ключ хранится только на сервере.
- Модерация: серверный модуль Артура, подключённый Алимжаном к API записи комментариев; клиентская подсказка Алинура дополняет серверную проверку.
- Файлы: локальные демонстрационные материалы или объектное хранилище с разрешёнными файлами; окончательное решение — после аудита объёма и прав.

Стек ещё не установлен. На этапе A03 подтвердить его с учётом опыта команды и доступного хостинга. Не тратить время хакатона на микросервисы. В P0 использовать текстовый поиск PostgreSQL; отдельную векторную базу вводить только при доказанной необходимости.

## Этапы и порядок

Длительность хакатона неизвестна, поэтому этапы заданы последовательностью, а не выдуманными сроками.

1. **Основа:** Артур выполняет аудит и готовит демоданные; Алинур проектирует страницы и состояния; Алимжан фиксирует модель и API. Результат: согласованный объём P0, макеты, схема данных, примеры запросов и ответов.
2. **Параллельная разработка:** Алинур делает интерфейс на моках по контракту; Алимжан — каталог, учётные записи и API; Артур — корпус, ИИ и модерацию. Моки не выдавать за интеграцию.
3. **Интеграция:** подключить реальные API; проверить путь «поиск → документ → избранное → вопрос ИИ → комментарий → жалоба → решение модератора».
4. **Стабилизация:** устранить ошибки P0, проверить доступность и мобильную версию, безопасность и ограничения ИИ, развернуть стенд.
5. **Презентация:** подготовить воспроизводимый показ, резервный сценарий и честно перечислить ограничения.

После каждого этапа каждый участник обновляет статусы своих задач в бэклоге. Если времени мало, сначала отложить P2, затем P1; серверную модерацию, защиту ключей и права доступа не исключать из P0.

## Готовность к показу

- Все P0-задачи выполнены либо явно отмечены как блокирующие; нет скрытых заглушек в основном сценарии.
- Поиск выдаёт ожидаемые документы, фильтры работают совместно, прямые ссылки на карточки открываются.
- ИИ приводит существующие источники и сообщает, когда ответа в корпусе нет. При отсутствии ключа интерфейс честно показывает недоступность; записанный пример не считается работающим ИИ.
- Комментарии с матом не публикуются через интерфейс и прямой API; подозрительные случаи проходят ручную проверку. Абсолютную защиту от всех обходов обещать нельзя: качество подтверждается тестовым набором.
- Пользователь не может модерировать, менять или удалять чужие комментарии; модератор видит только разрешённые действия.
- Основной сценарий работает на телефоне и десктопе, с клавиатуры, без критических ошибок и утечек секретов.
- Есть инструкция запуска, тестовые данные, результаты проверок, адрес стенда и резервный сценарий демо.
