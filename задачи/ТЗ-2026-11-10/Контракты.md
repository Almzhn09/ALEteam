# Совместные контракты новых функций — проект v1

**Это проект API, не описание существующих endpoint.** Утверждает/реализует транспорт и миграции Алимжан (COL-B01); Артур передаёт модули поиска/объяснения/ранжирования, Алинур использует опубликованные DTO. До реализации `src/contracts/discovery.ts` и соответствующих маршрутов фронтенд помечает фикстуры. Ломающее изменение — версия контракта и обновлённые примеры в том же PR.

Существующая основа: [каталог](../../docs/catalog/API.md), [CMS](../../docs/cms/API.md), [загрузки](../../docs/uploads/API.md), [импорт](../../docs/imports/API.md), [текущие DTO](../../src/contracts/api.ts), `src/server/{public-visibility,similarity,semantic-catalog-plan,notifications}.ts`. Существующий `/documents/:id/similar` возвращает TF-IDF результаты с score/commonTerms; `/me/notifications` связан с комментариями. Их нельзя незаметно заменить несовместимой схемой или объявить готовыми для всех новых функций.

## Общие правила

- Префикс `/api`; `locale=ru|kk|en` на всех новых текстовых чтениях, стабильные opaque ID отдельно от архивных шифров/названий. Точная локаль и `availableLocales`; при отсутствии перевода — явно указанный оригинал с `contentLocale`, `translationStatus:original`, без маскировки под перевод. Не менять поведение существующих endpoint точной локали.
- Ограниченные списки: `limit`1–20 (по умолчанию5), стабильный порядок с ID как tie-breaker, непрозрачный cursor там, где нужна пагинация. Все фильтры схемно проверяются, неизвестные поля/неверные интервалы отклоняются. Пустой `items:[]` — корректный результат, не сетевой сбой.
- Публичная проекция каталога и CMS с общими правилами видимости; самостоятельная проверка карточки/копии/OCR. Авторизация/филиальная область на каждом изменении. Скрытое меню или виджет не защищают данные. Ответ по закрытому/несуществующему публичному ресурсу не раскрывает его название.
- CSRF/Origin, HTTP-коды и `{error:{code,message}}` сохраняются из текущего API. Лимиты тела/времени/источников; 401/403/404/409/422/429/503 различаются и имеют пользовательские состояния. Новые коды предварительно фиксируются в DTO/документации; существующие ошибки не переименовывать без миграции клиента.
- Дата события: `datePrecision:day|month|year|range|unknown`, заполнены только известные части, `yearFrom/yearTo` по необходимости. Рукописный OCR не становится точной ISO-датой автоматически. Для алиаса/факта — источник, период применимости и статус проверки.
- `SourceRef`: `kind:document|cms`, `id`, `locale`, `revision` (опубликованная версия/устойчивый fingerprint), `href`, `title`; fragment — ID/реальная страница/диапазон при наличии. Версия цитаты привязана к тексту. Клиент не задаёт URL источника/путь к хранилищу для серверного чтения.
- `MaterialRef`: `kind`, `id`, `href`, `title`, `contentLocale`, `availableLocales`, необязательные разрешённые preview/дата, `reason:{code,text,evidence:SourceRef[]}`. URL формируется сервером, причина локализуется из проверенных данных. Скрытие материала немедленно исключает его из списка, кеша, уведомлений и ответов ИИ.

## Предлагаемые endpoint и транспорт

| Метод / путь | Запрос / назначение | Основные поля ответа и поведение |
|---|---|---|
| GET `/discovery/aliases` | `q`, `locale`, необязательный `entityType:place`, `limit` | `items:[{entityId,canonicalName,aliases:[{name,locale,validFrom?,validTo?,source,status}],ambiguity}]`. Не утверждает несуществующее равенство одноимённых городов |
| GET `/documents` (существующий API каталога; UI-страница `/catalog`) | Добавить **обратно совместимые** `nameMode:literal|expanded`, `placeId?`; остальные фильтры без замены смысла | Текущая выдача + метаданные применённого расширения. Не размножать совпадения; номер/шифр не нормализуется через словарь топонимов. Утвердить точные имена параметров в COL-B01 |
| POST `/documents/:id/explanation` | `{locale,sourceRevision?}`; источник только по ID из прав пользователя | `{status:ready|no_text|low_quality|unsupported,mode:extractive|glossary|grounded,sourceRevision,summary?,terms:[],citations:[],limitations:[]}`. При changed revision —409/перечитать; цитаты указывают реальные фрагменты. Backend не возвращает OCR закрытой копии даже с этим status |
| GET `/places` | `q?`, `locale`, `limit`, `cursor?` | Проверенные места с кратким описанием, availableLocales, реальным количеством доступных элементов; координаты nullable, `mapAvailable` объясняет наличие карты |
| GET `/places/:id/history` | `locale`, `yearFrom?`, `yearTo?`, `limit`, `cursor?` | `place`, `items:[{id,datePrecision,dateParts?,yearFrom?,yearTo?,title,body,materials:MaterialRef[],sources:SourceRef[],certainty}]`, `nextCursor`. Не смешивать карту действующих филиалов с историческими местами |
| GET `/documents/:id/related` | `locale`, `limit` | `items:MaterialRef[]`, `method:curated|metadata|text_similarity|mixed`; `reason.code:same_place|same_person|same_event|same_fund|text_similarity`. Оставить старый `/similar` совместимым; адаптер может переиспользовать его ранжирование |
| GET `/discovery/home` | `locale`; гостевые интересы — ограниченные ID тем, не произвольные скрытые документы/чужой userId | `recommended:{mode:editorial|interests|history,items}`, `popular:{status:measured|unavailable,period?,items}`, `continue:{scope:browser|account,items}`; причины/данные только разрешённые. Сервер не обещает account history для гостя |
| GET/PUT `/me/interests` | PUT `{topicIds:[],personalizationEnabled,historyEnabled}`; свои настройки, явный выбор | `item`, сохранённая версия/время; очищение и выключение реально меняют выборку, удаление истории отдельным явным действием. Для гостя допустим локальный выбор без передачи просмотра |
| POST `/discovery/events` | Только если вводится согласованный сбор: ограниченный тип события `view` + публичный ID + дедупликация/лимиты; без текста чата/сырого поискового запроса | Не рисует фиктивные счётчики. Правила периода/ботов/повторных просмотров описаны. Для популярности достаточно агрегатов без привязки к аккаунту; сбор пользовательской истории отделён и требует включения |
| GET/POST `/me/topic-subscriptions` | POST `{topicId?,placeId?,filters?,locale}` с белым списком ключей/нормализованным fingerprint | Только свои `items`; создание повторной активной подписки идемпотентно. Фильтры фиксируют смысл/режим алиасов; baseline задаётся при создании на стороне сервера |
| DELETE `/me/topic-subscriptions/:id` | Отказ от своей подписки | Идемпотентно/без доступа к чужой записи; последующие события не доставляются |
| GET `/me/topic-notifications`; PATCH `/me/topic-notifications/:id` | Пагинация/read, только свои данные | Отдельный endpoint до безопасного объединения с comment notifications; содержит subscriptionId/materialRef/readAt/createdAt, не тело закрытого источника. Удалённое/отозванное совпадение не отображается |
| POST `/assistant` (существующий) | Прежние question/history/locale; исследовательский режим как обратно совместимое расширение | Сохраняются старые `sources`/`catalogQuery`; добавляются `researchSteps?` и `actions?`. `actions` — типизированные `catalogSearch|openMaterial|openPlace`, параметры проходят серверную схему и те же права. Не отдавать произвольный JS/внешний URL как действие |

Имена новых endpoint можно уточнить один раз в COL-B01: финальный DTO + матрица различий + пример запроса/ответа публикуются прежде подключения. Новые зависимости не добавлять только ради DTO. Параллельные движки и фронтенд не создают разные имена одного и того же поля.

## Интерфейс модулей Артура и транспорта Алимжана

В COL-B01 создать общие browser-safe типы в `src/contracts/discovery.ts`. Сигнатуры движков фиксируются там/в соседнем согласованном server-only файле; предполагаемые операции: `expandNames`, `rankRelated`, `rankRecommendations`, `explainFragments`, `planResearch`. Движкам передаётся **уже отфильтрованный по правам снимок**, locale и версия источника. Они возвращают ID/причины/цитаты/структурированные действия, а не читают произвольные файлы/маршруты/учётки.

Алимжан владеет fetch/DB/лимитами/валидацией/доставкой/маршрутами и повторной проверкой видимости перед ответом. Артур владеет интерпретацией/ранжированием/достоверностью; Алинур не воспроизводит эти правила в браузере. Опасную серверную выборку нельзя оправдать последующей фильтрацией модели.

## Обязательные тестовые примеры в контрактном PR

1. Алтай/Зыряновск + ограничение годов; literal отличается от expanded; неизвестный одноимённый объект требует уточнения; буквенный шифр не меняется.
2. Публичная карточка с закрытой копией: метаданные доступны, объяснение/OCR и цитаты закрытого файла не выдаются. Отзыв источника делает старое объяснение/связь/кеш недоступными.
3. Публикация новой редакции вызывает пересчёт подписки; retry/повторный publish не дублирует уведомление. Начальные совпадения не считаются новыми. Другой пользователь не читает/меняет подписки.
4. У гостя без интересов/истории — редакционная подборка. У пользователя с отключённой персонализацией не используются прежние предпочтения/просмотры. Измерений нет — статус unavailable, не выдуманные popularity scores.
5. Отсутствующая локаль, мало материалов, нет координат, низкое качество OCR, недоступный движок — понятный результат без ложного перевода/«пустого успеха».
6. Новые поля `/assistant` и новые notifications не ломают существующий фронтенд/13 release-сценариев; реальные UI-подключения проверяются отдельно от контрактных фикстур.
